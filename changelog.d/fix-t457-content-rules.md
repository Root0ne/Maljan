### Fixed

- **The analyst report prints a drafted rule only where it matches its sample by content, each with a Precision line (T-457, T-473).** The YARA draft matched the published indicators, which a sample that keeps them encoded holds in no byte, so on the stored Latrodectus runs it matched its own sample by its sha256 and import hash only (0 of 5 strings found), and the analyst report printed it anyway. A file rule now prints its body in the analyst report only where its strings clause held on the sample; one that matched by a hash alone, was not run against the sample, or was stored before that check is named in §8.2 with the reason, and the evidence bundle and the single-file report still print every body. Every rule the analyst report prints carries a Precision line saying what it was measured on, published strings and stored values counted apart, and that no retro-hunt was run; §8.2 also counts the stored values the draft leaves out. A value the code passes to an API argument now says in the analyst report's indicator table where the code decoded and loaded it, which only the draft's comment had carried there; the whole chain stays in the bundle.
- **The YARA draft matches the values the sample stores as they are (T-457).** A decoder's seed, which a seed-and-length header stores in front of each encoded string, and each function-name hash a resolver found in the file are read from the ledger through the answer's declaration (`reporting.code_constants`, the consumer `code_constants`; the built-in decoder and resolver now declare `seed`, `value` and `algorithm`; kept in the report's `code_constants`). They are drafted as hex strings: every seed (`$dN`) together with a quantifier of the hashes (`$hN`). A function-name hash is how a program finds its imports, which programs resolving by the same public algorithm share, so hashes never count without a seed, and a run with no seed or fewer than two hashes drafts none and says why. A value below 0x10000 or of fewer than three distinct bytes, a hash whose algorithm resolves no second value in its answer, a lone hit and an answer about a carved file are not read; past the caps the draft says how many it left out. A draft with none of them is written as before.
### Added

- **A hunting query in the analyst report's §8.3 (T-457).** Built from the published user agents and URL paths (a path of fewer than three characters besides its slashes is left out), with the published hosts excluded, so a match is a candidate for more of the same infrastructure; printed live in a code block, in neutral field names, with control, format and separator characters dropped. A run that drafted no rule prints none, and renders byte for byte as before.
