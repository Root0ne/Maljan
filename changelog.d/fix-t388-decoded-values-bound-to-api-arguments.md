### Fixed

- **A decoded mutex name, file path or user agent is published where the code passes it to the API argument that takes it (OWN-T388).** Such a value used to stay a candidate on every surface, because its shape alone is no source: a run decodes user agents its code never uses. The report now binds a decoded text only where the run's own answers state the whole chain: the static decoder's reference hands the encoded bytes to a routine of the file, the frame slot that routine was given (never its return value) is an argument of the next call, directly or inside the function that call reaches, the call is an import the file's table names or a slot one function index entry names alone, and a new argument-role table (`data/api_argument_roles_v1.json`, written from the Win32 prototypes) says that argument of that API takes a mutex name, a file path or a user agent in the text's encoding. A file path binds only where the call makes or removes the file: a copy's or a move's destination, a download's file, a delete, and CreateFile only with a constant creation disposition that creates the file. The bound value is an IOC row under the `call_argument` source, and the chain (entry, call, argument) is its reason in §9, `/iocs`, the MISP comment and the STIX indicator's description. A user agent's STIX pattern compares the `User-Agent` request header (`http-request-ext`). One that begins as the common browsers' do (`Mozilla/5.0 (` and the like) keeps its row and chain but is refused with that reason, because an indicator for it would match ordinary browser traffic; the prefix rule is conservative and also leaves unpublished a browser-shaped agent with a distinctive token of its own. Nothing bound publishes under a Benign verdict or one stated without a confidence. The static decoder now follows the decoded text one function deep (`inside`), states a called API's constant stack arguments (`constants`), and says on each such hop whether the followed buffer reaches the call as the decoder left it (`contents_unchanged`: false after a store into it, a store through a register holding it or a frame address, a string store, an indexed frame store, or a call given a frame address on the way); only an unchanged buffer binds, and the hops it states are the ones it stated before. A judge value the report binds is asked as the binding; a user agent nothing binds is refused with that reason. A report stored before this renders as it did.
