### Fixed

- **A published user agent gets a Suricata rule (T-498).** The Suricata draft read the published domains, addresses and URLs only, so a user agent the run publishes from the call that sends it had no rule. Each published user agent now gets an `http.user_agent` rule that matches the header whole (`startswith; endswith;`), as the STIX pattern compares it, so a published `Mozilla/5.0` never matches every browser. A value of fewer than eight bytes, spaces aside, gets none. The rules follow the others so their SIDs do not move, carry the publish reason in the comment above them, and have the per-kind cap and its closing note as the other kinds have.
- **A Suricata content writes a character beyond ASCII as its UTF-8 bytes (T-498).** Every draft's content wrote such a character as its code point in hex, so `é` was `|E9|`, which no request carries, and a character above U+00FF was a group a sensor refuses. Each is now its UTF-8 bytes, one `|XX|` pair each, and the draft's syntax check refuses a `|...|` group that is not hex byte pairs. A backslash in a rule's message, which could come from a family name, is written as `/`. Every stored run's drafts are unchanged: their values are ASCII.
