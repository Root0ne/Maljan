### Security

- **A token alone before the `@` of an address written with no scheme is masked whole when it holds a quote or a bracket, and registered with the event scrub (T-371).** `p"ss@llm.internal:8080` was read from its last opener, so the masking kept `p"` in front of `***@llm.internal:8080` and the event scrub registered only the part after the quote, where it had a token's shape. A token with no colon before its `@` is now read from the word's leading openers where nothing after the `@` closes the opener inside it, so every character before the `@` is masked (`***@llm.internal:8080`), and the whole token is registered with the event scrub, with the part after its last opener where that has a token's shape. A closed opener quotes the address and what stands before it is kept, as before: `func("***@host:22")`, `url="***@h:8080"`, `require("@scope/pkg")`; so a token whose own quote is closed after the `@` (`p"ss@h:8080",`) still keeps what stands before that quote. A mail address, `user@host` and `@name` are kept as before. A registered value shorter than eight characters is masked where the address is masked, but a later event that repeats it is masked only in finding rows, as every short configured value is.
- **A password escaped in JSON text is masked.** A backslash before the `@` made the address read as a Windows path, so `{"password":"p\"ss@h:8080"}` was kept whole. Where the address names a port or a path, only a backslash that escapes neither a quote nor a backslash marks a path now; before a mail address's host any backslash still refuses the reading, so `{"to":"\"bob\"@corp.com"}` and `C:\Users\bob@corp` are kept as written.
