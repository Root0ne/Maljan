### Fixed

- **A model's endpoint prints as configured only where the run's own record says so, so a stored report renders the same on every machine (T-363).** A rate line in the run summary's appendix printed a model's endpoint (`<model> @ <endpoint>`) undefanged when the settings of the process rendering the report configured it, so one stored report printed `http://127.0.0.1:8080` on a machine whose settings named that endpoint and `hxxp://127[.]0[.]0[.]1:8080` everywhere else. The run's disclosure record now keeps the labels of the model endpoints its settings configured (`endpoint_labels`: scheme, host and port, written by the function that writes a model's label, so no credential, path or query is kept), as it keeps the hosts its settings addressed, and the renderer reads only those; the disclosure record's version is 4. A run stored before the field renders as it did where no model endpoint was configured: its endpoints print defanged. The process's settings are never read for this, and the test fixture that pinned stored renders to a machine without a configured endpoint is gone with the dependency.
- **A host the run's settings address is kept in the disclosure record when a configured key's text is part of it.** The record read its addressed hosts off the settings snapshot, whose secret scrub masks a configured secret's text wherever it appears, so an `ollama` key beside `http://ollama:11434` recorded the host as `***` and the report printed it defanged. The addressed hosts and the endpoint labels are now read off the job's own settings, with every URL's credentials masked; the snapshot is read only where no settings are held.

### Security

- **An address written with no scheme no longer keeps its credentials in the run's settings snapshot, the console's settings read, the export or a logged error.** `user:password@llm.internal:8080/v1` was masked only with a scheme in front of it. Everything before its last `@` is now masked (`***@llm.internal:8080/v1`), a password holding `@` or an encoded `%40` included, in a quoted value or a compact JSON member too (`{"***@host"}`: a colon before the last quote may be the password's own, so the key is masked with it), a password holding a quote or a bracket included, and its password is registered with the event scrub as a URL's is. Free text is read word by word, so only the password of an address in a sentence is registered, never the sentence. A mail address, a mailbox after its scheme or header (`mailto:ops@example.com`, `From:alice@example.com`, never one followed by a second colon, a port or a path), a Windows path, a package pin (`pkg@1.2.3`, `@scope/pkg@latest`), a Git remote and an image digest are kept as written.
