### Fixed

- **A stage none of whose analysts holds any of the data they read is skipped, and says why (T-503).** A team with a stage of its own for an analyst that reads only the sandbox report announced that stage as started on a job no sandbox ran for, built the analyst and attached its tool servers, and recorded the stage as having run. Before an analysis stage starts, each analyst's declared reading is now set against the data the job holds (`pipeline.data_needs`): its input slice (its `data_sources`, else its role's) and the sources of its tools, where the job's sandbox report source reads the sandbox report and every tool server the agent reaches, by reference, capability or the server's own `agents` list less what its profile withholds, reads only job data when every role its declaration names is tied to a kind (`capture`: a packet capture or the report's network rows; `reference`: no job data, its tools take no path). A stage whose every analyst lacks every kind it reads is skipped: no analyst is built and no model is called. A role handed the sample, any server over the sample (a reputation lookup, a static provider), a server that declares no role, an ask of another agent, an undeclared agent, stored data for the sample, or findings injected from a stage it depends on that found something keeps the stage running; a decision that cannot be read runs it.
- What changes for a new run of a staged team with such a stage: its stage record reads `ran: false` with the kinds it lacked as its reason and `dataless: true` (each analyst's own reason stays the no-data guard's, such as "no sandbox fixture for this sample"); the console receives `stage_skipped` with the reason instead of `stage_started`; each analyst's line is the no-data guard's skip line; its analysts are no longer members of the debate that follows (they were never revised); and the verdict's degradation reasons name them skipped by what they lacked, in team order, in the same words as before. The mock pipeline is unchanged, and so is every job whose stages hold data: over the stored benchmark runs no stage would have been skipped.
