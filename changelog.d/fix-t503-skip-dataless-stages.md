### Fixed

- **A stage none of whose analysts holds any of the data they read is skipped, and says why (T-503).** A team with a stage of its own for an analyst that reads only the sandbox report announced that stage as started on a job no sandbox ran for, built the analyst and attached its tool servers, and recorded the stage as having run. Before an analysis stage starts, each analyst's declared reading is now set against the data the job holds (`pipeline.data_needs`): its input slice (its `data_sources`, else its role's) and its tools' sources, where the job's sandbox report source reads the sandbox report and a tool server or capability reads only job data when every role its declaration names is tied to a kind (`capture`: a packet capture or the report's network rows; `reference`: no job data). A stage whose every analyst lacks every kind it reads is recorded as not run with the reason, `stage_skipped` carries the reason to the console, no analyst is built and no model is called; each analyst leaves the skip line and empty ISR the no-data guard leaves, and the verdict's degradation reasons name it skipped by what it lacked. A role handed the sample, any tool over the sample (a reputation lookup, a static provider), a server that declares no role, an ask of another agent, an undeclared agent, stored data for the sample, or findings injected from a stage it depends on that found something keeps the stage running; a decision that cannot be read runs it. The mock pipeline is unchanged, and so is every job whose stages hold data: over the stored benchmark runs no stage would have been skipped.
