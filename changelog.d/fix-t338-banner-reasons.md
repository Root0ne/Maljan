### Fixed

- **The DEGRADED RUN banner rests on every loss and only on losses (T-338).** A tool a shared server withholds by its configured policy (`job_safe_tools`, `shared_withheld_tools`), a tool whose manifest cell carries the new `code` `not_configured` while the platform holds no value for the setting (a threat-intel key never configured) and a referenced tool of a server switched off were listed among the degradation reasons, and the withheld ones made the run degraded: one run drew the banner from sixteen withheld Ghidra project tools and three unset keys. They are now listed apart as the operator's choices (`operator_choices` in the report and the run summary, "Not configured or withheld by choice" in §13 and in the console's run record, a line of its own in the rehearsal gate's output, a section of its own in the run comparison) and the judge is told them as absences, not as limits of the run. The other way round, every loss now makes the run degraded: a tool missing its library or binary and any triage pack tool that failed (capa included) used to be called optional and drew no banner, so a run that went without capa read as a full one. The banner names each tool the run went without ("the run went without capa"), from the same decision that sets the flag. A tool serving only other formats than the sample's (a Mach-O parser on a PE) costs it nothing; a tool that still answers part of what it would degrades the run only where the part it lacks is the sample's or the tool answered the run with its missing-dependency error: `archive_list` without py7zr loses a PE or zip sample nothing and a 7z sample its reader (`ToolNeeds.without_reads`); a tool that declares none, or a run with no format, counts it as a loss. A tool schema whose parsed arguments come out empty while it holds `$ref`, `allOf`, `anyOf`, `oneOf` or a required list is withheld as unread, a loss, rather than by policy. The dashboard's notice says a setting left unset is not configured rather than that it degrades a run, and the run comparison pairs a stored run's choice with a newer run's. A failed fetch, a tool error, a cap, a timeout and a tool withheld because its schema could not be read stay degradations as before. No reason leaves every surface: the surface checker now looks for each reason and each choice in the Markdown, the HTML and the run summary. Stored reports read as before; the replay moves a stored choice to `operator_choices`, names the move and decides again whether the run is degraded. A `not_configured` claim counts only for a setting the platform can hand that server and holds no value for, with the probe's exact words, and a manifest naming another server's key speaks only for its own. A report stored before manifests carried the code reads every such reason as a loss, the safe direction: its banner names the unset-key tools as tools the run went without, which is all its record can prove.
