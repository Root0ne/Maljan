### Fixed

- **An MCP tool argument named what a pydantic field or a Python keyword argument cannot be named now builds, is offered and reaches the server under its own name (T-360).** A property named `model_config`, `model_dump` or `model_post_init` crashed the build, so the whole tool was lost; a name with a leading underscore (`_x`, `__x`) became a private attribute, so the argument was neither offered nor sent; a `BaseModel` member such as `schema` or `json` shadowed it with a warning; a keyword or a name that is not an identifier (`class`, `from`, `a-b`, `1x`) was sent but never offered to the model; and `self`, `config` or `run_manager`, the keywords of the tool's own call, crashed the call or lost the argument. Such an argument is now held under an internal field name with the server's name as its alias: the model is offered the server's name, its value is checked under it, the T-330 null rules read it, the call sends it to the server unchanged, and the ledger records, cites and keys a repeat of the call by that same name, which the path, capture and sample-open guards also read; this holds through the recorder, the declared-error and path guards and the sample opener that rebuild a tool around it. Every other argument is a field of its own name, and every tool of the built-in MCP servers and the VirusTotal tools is offered what it was.
