### Fixed

- **The report model's host identifier table says which of its values are published (T-386).** Its footer said "These rows are not published", which was false for the rows the IOC table publishes: on the stored runs the C2 URLs and domains, and the `runnung` mutex where the judge named it. The footer now says the table publishes nothing itself and that a value it lists is published only where the IOC table publishes it, and each row whose whole value the IOC table publishes is marked with the §9 table that does ("published in the Network indicators table", "published in the File and host indicators table"). The HTML report reads the same Markdown; the console's panel, which does not load the IOC table, carries the general footer. On the six stored runs only the footer and 1 to 4 marked rows per run change.
- **A user agent, JA3 or JA3S the sandbox recorded is no longer published on its record alone (T-387).** The IOC table answered each `yes: sandbox` with no rule asked, so `/iocs` and the MISP attributes published it while the STIX export, which has no object for one, did not; the same capture's addresses that no process of the sample's tree reached were refused. The capture records no process beside these values, so each is now refused under the unattributed rule ("the sandbox report does not say which process made the traffic it was read from") on the table, `/iocs`, MISP and STIX alike. None of the stored runs records one, so their reports are unchanged.
