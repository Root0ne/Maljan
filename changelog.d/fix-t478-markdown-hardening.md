### Fixed

- **The HTML and PDF report decide on a link as written and drop nothing past the nesting bound (T-478).** A link's or an image's target spelled with a character reference (`[a](https&#58;//x)`) was decoded before it was checked, so it became a live link, and it stayed text only because the Markdown writer escapes every `&`. The renderer now reads the target as the source wrote it and refuses one that holds a reference, for a link, an image and a reference definition alike; a plainly written target links as before. A block markdown-it stopped reading at its nesting bound (a quote 25 deep) lost its text; that block is now shown as its source, escaped in a `<pre>`, as the console shows it, and every other block renders as before. Every stored run's report renders byte-for-byte as it did.
