### Fixed

- **The commands table lists only what the sample started (T-494).** The "commands the sample started" table in the analyst and the full report listed every process below a root of the sandbox's process tree, so a desktop process the sandbox marked (haiku8: `explorer.exe /LOADSAVEDWINDOWS`, pid 95, under sihost.exe) was printed as the sample's. A command is now listed only when it descends from a process that runs the submitted file (its name or its digest); the sandbox's mark alone never makes it one. A command left out is said under the table, with its pid and where the process tree is. The IOC table, the STIX processes and the exports are unchanged.
- **A sentence calling a read routine "not read" is asked against its listing (T-494).** The agreement round was shown the routines no entry lists, but not the ones an entry does, so "Its body was not read" (0x7504) and "their code is not in this evidence" (0x7504, 0xd1c8) stood beside the listing in ev_0175. The round is now shown, as a platform fact (`listed.N`), each routine whose code an entry lists where a passage names it in a sentence that, or whose next sentence, calls code not read or not in the evidence; a section 5 sentence it contradicts is qualified in the platform's words, like the other ledger facts. The platform's own unread-callee clause names no routine for this, so the facts stay few (0 to 8 on the stored runs).
- **The ATT&CK procedures are asked for agreement too (T-494).** The one-sentence procedures of the ATT&CK table are written from the claims beside section 5 and were never shown to the agreement round, so "the hidden-window setting is not established" (T1564.003) stood beside section 5's SW_HIDE. Each procedure is now a passage written without the code, which the round may rewrite on section 5, a fact or a closed debate line.
