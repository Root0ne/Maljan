### Fixed

- **The analysts and the judge are told when the live sandbox report names another target (T-322).** A live sandbox report whose target SHA-256 is not the sample's intake SHA-256 was compared only after the graph, for the run summary and the disclosure record, so the analysts and the judge read its behaviour as the sample's without being told. The run now makes the same comparison before the graph runs, from the neutral report's target hash only, whichever sandbox ran, and marks the report (`target_not_the_sample`, the two hashes). The pack's `sandbox_status` step then states it before the sandbox views, in the disclosure record's words: the report names its target SHA-256 as one hash, not the sample's intake SHA-256: what it observed may be of other bytes, and which findings it touches is the analyst's call. A target value that is not a SHA-256 is the sandbox's own text and is shown as one bounded line with credentials removed. The report stays an observation: its status reads `observed` everywhere it did, and the report's Sandbox section carries the sentence. A report whose target is the sample, that names none, a recorded fixture and the mock sandbox's stand-in are unchanged, byte for byte; a block a sandbox published under the mark's word is taken out with a warning, since the word is the platform's. An operator profile that drops the `sandbox_status` pack step drops this sentence with it; the run summary's `sandbox_target` record and the disclosure line are written as before.
