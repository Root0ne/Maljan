### Fixed

- **The check that every backend service which starts a tool server mounts the same trees now also reads the development overlay merged over the production file, and compares where each tree comes from (T-459).** Each compose file was checked on its own and only by container path, so an overlay that remounted a tree in one service and not in another, or from another host directory, passed although `make dev-up` would start the stack with a trust grant that holds in one service and not in the next. The overlay is now merged per service, volumes by their container path as compose merges them, and the merged stack must mount the same `/app` trees in every launching service, each from the same normalised source and of the same kind (a bind, a named volume, an anonymous one), in short or long syntax; a mount's mode is not compared, so the overlay's read-write source trees still pass. The per-file check stays. The current files pass unchanged.
