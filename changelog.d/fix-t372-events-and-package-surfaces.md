### Fixed

- **The job package's `report.md` is the served Markdown, byte for byte, and the surface checker reads the completed event as the API serves it (T-372).** The served Markdown, HTML and PDF rendered the stored report in the key order Postgres JSONB returns (shorter keys first), while the package rendered it from the run export, written with sorted keys; wherever the renderer lists a mapping in its given order (import capabilities with the same count, the model calls per role, the repeated tool calls per maker, each role's output tokens, the tool servers at attach) the two listed the same entries in a different order. Both now read the stored report in sorted key order, so the served exports list those entries alphabetically, as the package always did; no entry, count or word changes, and the package is unchanged. The checker read the completed event's verdict, confidence and report id only under `payload`, the key a stored run's `events.json` keeps, while `GET /jobs/{id}/events` serves them under `data`, so every live job reported all three as missing although the worker emits them; it now reads either. Events, stored reports and stored runs are unchanged.
