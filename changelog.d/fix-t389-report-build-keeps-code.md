### Fixed

- **The report build keeps a function's code whole in the table that holds it (T-389).** Every value a generic evidence table stored was cut at 400 characters, so decompiled and disassembled functions reached `report.json` cut: 55 of haiku6's 78 code bodies ended in "…" (haiku5 38 of 46, run5 56 of 65), and every surface drawing them, the console's tables and the appendix listings among them, could show only that. A value is now kept whole when the entry it came from stored a decompile or disassembly kind with its facts, or when it names the function its row names (`FUN_00401000` under `0x401000`); never by a tool's name. A one-line value, and a text of several lines that is no code, is still cut at 400 characters as before. Rebuilt offline, only those code cells change: `report.json` grows by 68,502 bytes on haiku6 (2.9%), 50,017 on haiku5 (2.2%) and 107,595 on run5 (6.8%), and not at all on haiku4, run7 and local8, which stored no cut code; the export, the IOC table, MISP and the verdict are the same.
