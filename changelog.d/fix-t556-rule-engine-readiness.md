### Fixed

- **A rule engine that loaded no rule did not run, and says so (T-556).** Three runs scanned the sandbox report's events with no Sigma corpus (it is fetched rather than tracked, and the run's worktree had none): the worker logged a warning, the entry held `rule_count 0`, the report said "Sigma (0 hits)", the run was not degraded, and the check before the job named nothing. Sigma, YARA and capa now answer a corpus that loaded no rule as a failure with the `missing_dependency` code and the declared data path's remedy, so the triage pack records the step failed, the run is degraded, the header names the tool and the report's scope (§2) says what the run went without and why. `POST /jobs` and the system status now also look at every enabled in-process pack step that no reading stands in for and whose tool a sidecar declares, in the worker's environment, whatever the server's block says; the YARA corpus is declared too (only an override can name it missing), `MALJAN_YARA_RULES_DIR` may name a directory of rule files as its name says, and a corpus that loaded nothing is no longer kept for the process's lifetime, so one put in place later is read without a restart. A tool missing its data no longer says what it "still answers".
