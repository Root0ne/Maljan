### Fixed

- **A stdio tool server's argument is rooted at the project only where it stays inside it (T-530).** Arguments were rooted by a looser rule than the command: an argument whose first component existed under the project was joined onto it as written, so `../x`, `./../x` and `scripts/../../x` were rooted to a file outside the project. Arguments are now rooted by the command's rule (T-461): a relative path is rooted only when its first component past any leading `./` exists in the project and the normalised path stays inside it, and `\` is a separator only on Windows. A relative path that leaves the project reaches the child as written, read from the directory the child starts in, and the launch says so in a warning naming the server and the argument. The launch and the console trust grant read the same argument, so a grant recorded for an argument once rooted out of the project no longer holds where the child now starts a different file. A path that leaves the project through a link (`link/passwd` where `link` points outside) counts as leaving it, as a working directory's does. A `./`-prefixed argument whose first directory does not exist yet (`./out/new.json`), and a bare `./`, are no longer rooted at the project. Write `data/...` or an absolute path for an output that must land in the project. Flags, URLs, `-x=val` forms, bare words and absolute paths are unchanged, and so are the arguments of every shipped server block.
