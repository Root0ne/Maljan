### Changed

- **A tool loop past its model's price tier clears the answers it already cited (T-340).** Where the agent's own model is priced by prompt length (its price row's `tiers`, from `llm.model_prices` or the vendored table; Claude Haiku 5.5 bills a prompt over 100,000 tokens at five times the rate) and a loop's next request is past the first boundary, the oldest tool answers whose evidence id one of the model's own turns has already written in its text become `[cleared ev_…]` references that `read_evidence` reads again, as a window clear makes them. An id named only in a call's arguments or in the model's reasoning is no citation, and an answer the model has not cited is never cleared for the tier. The clear is made only where what no tier clear can take is already under the boundary and where the request it sends, written to the cache whole, costs less at the model's prices than the one it replaces with its cached prefix, the turn's answer priced at the loop's mean and every write priced for an hour where the model's cache entries live that long (`tool_answer_clearing.tier_clear_pays`). A model priced by no prompt length is never cleared for it. `tool_answers_cleared` names the new reason `tier`. Replayed through the stored haiku5 loops (`tests/fixtures/clearing/haiku5_tool_loops.json`), every id a loop's answer cites stays whole or re-readable, and no loop clears anything at either cache lifetime (the reverser's first request alone was 131,680 tokens; the other loops that crossed the boundary had cited too little of what they read), so that run is sent as it was.

### Fixed

- **A repeated call is known by the address it names when it was first written with `0x` (T-340).** The repeat guard keyed every spelling of an address apart. An argument named for an address in the binary (`undeclared_tools.named_as_address`) is now keyed by its value where it is written with `0x` (`0x1360BC03868` and `0x1360bc03868` are one call), and a bare spelling is answered from an entry a `0x` call made where it holds at least one decimal digit and one hex letter and the argument's name has no `name` word. A `0x` ask is never answered from an entry a bare call made, since a tool nobody declared may read the bare form otherwise; haiku5's round-3 reread of 0x1360bc03868 (ev_0128, prefixed, after the bare ev_0121) is that direction and still runs. Every other argument is compared as written.
