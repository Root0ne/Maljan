### Fixed

- **Every function a batch decompiled reaches the report writer, once, with its citation (T-334).** The composer's technical sections read only the `decompile` and `function_disassembly` kinds, so a batch decompile (kind `decompile_batch`) reached none of them: on a stored run 34 of its 51 decompiled functions, the command switch and the beacon loop among them, were never shown, and the report said decompile results existed for three functions only. Decompiled code is now read as `decompile` whatever tool gave it, and the functions a batch's answer lists (an object keyed by address, the declared `rows`, or a list of rows each holding code under a code key) form one run-wide table: each function once, its address in one spelling (`0x1360bc03868`, `1360bc03868` and `FUN_1360bc03868` are one), with the citation of every entry that listed it, written as the ledger cites a part of an entry (`ev_0068 (function 0x1360bc033ac)`) and only where the evidence index names that entry's tool and agent. A function's code is shown whole in each section a claim of which names it, or cites its entry naming none of that entry's functions (a claim that names some functions of a batch it cites is shown only those), else in `commands`; every other section that reads code gets one line for it (its citation, its size and where its code is). The claims and the tool answers keep the share of the window they had, and a prompt the code takes past a model's window is stated. A body a single decompile already shows is not repeated. The code-listing figures draw each function once, and "Functions examined" lists each function a batch decompiled that no other line lists, beside the batch's own block as before. A batch cut for storage is read member by member to the cut, and its last function says the answer was cut and later functions are not shown. A tool that declares nothing is read the same way only when each function of its answer names the function it stands under (its decompiler name, or its first instruction's address): a string table, a cross-reference map or a rule's matches keyed by address is not code, and four bare digits are no address. A declared single decompile is one listing whatever its answer's shape, and an entry with no recorded source is read as it always was. Stored reports re-render byte for byte.
