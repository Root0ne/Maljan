### Security

- **A cookie, a JWT, an `AUTH` entry and a password named run together with its owner are read as credentials (T-488).** The rule that says whether a mapping key names a credential value (`settings_catalog.names_a_credential_value`), which the event scrub's configured values and masking by value both read, missed `PGPASSWORD`, `COOKIE`, `SESSION_COOKIE`, `JWT` and `AUTH`, so a tool server's `env` value under such a name was masked only where it stood and never by value. `auth`, `cookie` and `jwt` are now credential last words, and a last word ending in `password` or `passwd` is one (`PGPASSWORD`, `MYSQLPASSWD`). The words are whole, so `author`, `authority`, `oauth_url`, `AUTH_MODE`, `AUTH_TYPE`, `AUTH_HEADER` (a header's name), `COOKIE_SECURE` and `JWT_ALGORITHM` stay settings. A value that names an authorization scheme or a switch (`basic`, `bearer`, `digest`, `negotiate`, `ntlm`, `kerberos`, `oauth`, `oauth2`, `anonymous`, `enabled`, `disabled`, `required`, `optional`) is a setting whatever its key says, as a number and `true`/`false` already were, so `AUTH=disabled` takes no word out of an event. A URL's `auth`, `cookie` or `jwt` query value is masked in events as an `api_key` one was. No shipped setting or declaration holds a value under a newly read name, and the stored runs replay the same.
