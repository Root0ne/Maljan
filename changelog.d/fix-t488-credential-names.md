### Security

- **A cookie, a JWT, an `AUTH` entry and a password named run together with its owner are read as credentials (T-488).** The rule that says whether a mapping key names a credential value (`settings_catalog.names_a_credential_value`), which the event scrub's configured values and masking by value both read, missed `PGPASSWORD`, `COOKIE`, `SESSION_COOKIE`, `JWT` and `AUTH`, so a tool server's `env` value under such a name was masked only where it stood and never by value. `auth`, `cookie`, `cookies` and `jwt` are now credential last words, and a last word ending in `password` or `passwd` is one (`PGPASSWORD`, `MYSQLPASSWD`). The words are whole, so `author`, `authority`, `oauth_url`, `AUTH_MODE`, `AUTH_TYPE`, `AUTH_HEADER` (a header's name), `COOKIE_SECURE`, `cookies_enabled` and `JWT_ALGORITHM` stay settings. A value that names an authorization scheme or a switch (`basic`, `bearer`, `digest`, `negotiate`, `ntlm`, `kerberos`, `oauth`, `oauth2`, `anonymous`, `enabled`, `disabled`, `required`, `optional`) is a setting whatever its key says, as a number and `true`/`false` already were, so `AUTH=disabled` takes no word out of an event. The structural masking where a value stands is unchanged by that list: an `AUTH=basic` entry is still shown masked. A URL's `auth`, `cookie` or `jwt` query value is masked in events as an `api_key` one was, while `author` and `oauth` are kept. The one shipped key newly read by the rule is the REST sandbox's `sandbox.rest.auth` block in a stored settings map: it is read key by key, so its `header` and `scheme` stay shown and only its `token` is masked and held. A tool server's command-line flag whose first word switches a credential on or off (`--no-auth`, `--no-password`, `--disable-token`, `--skip-…`, `--without-…`, `--require-…`, `--enable-…`) takes no value, so the argument after it is no longer masked as one; `--auth T` and `--auth=T` still mask `T`. No shipped setting or declaration holds a value under a newly read name, and the stored runs replay the same.
