### Fixed

- **A browser-shaped user agent that carries a token the browsers do not send is published (T-401).** A bound user agent that began as the common browsers' do (`Mozilla/5.0 (`, `Mozilla/4.0 (compatible; MSIE `, `Opera/`) was refused on the prefix alone, so one that is an Internet Explorer header with one more comment entry, a token of its own, reached neither STIX nor `/iocs`. The header is now read as its grammar (products and comments, RFC 9110 section 10.1.5) and each product name and comment word is asked against a vocabulary of the tokens the mainstream browsers, engines, in-app and embedded browsers and platforms send, with the Internet Explorer era's toolbar, runtime and OEM words, listed beside the prefixes in `data/api_argument_roles_v1.json` (`browser_user_agents.tokens`). A word is read past only in a shape the vocabulary states: a version (digits, dots and underscores) or a build of digits, one capital letter and digits (`15E148`), never `7zip`, `5a` or `1evil`; a version of digits, dots, underscores and hyphens after a listed word's `/` or `:` (`rv:121.0`, never `rv:evil` or `rv:1evil`); a version run onto a listed word (`InfoPath.2`, `GTB7.5`); a locale (`en-US`) or a bare ISO 639-1 language code from `languages`. A few words are a browser's only in context: `Core` beside `QQBrowser`, `MQQBrowser` or `Whale`, `VR` beside `OculusBrowser` (`products_beside`), `One` right after `Xbox` (`comment_words_after`), and the OEM words `NP06` to `NP09` rather than any `NP`. A token outside the vocabulary makes the value publishable, and the publish answer names it ("it begins as the common browsers' user agents do, but carries 'Tob 1.1', a token their own user agents do not send"). A well-known crawler's own token (`crawlers`: Googlebot, bingbot, YandexBot and the like, as its name alone or with its version and nothing more, so `Googlebot/Tob` is distinctive), with or without an info URL at that crawler's own domain right after it, is not such a token, and its header stays unpublished: an indicator on it would match that crawler. An info URL at any other host, or a bare `+http://host` entry anywhere else, is distinctive. An ordinary browser header still reads as a browser's and stays unpublished, and so does a header that cannot be read as the grammar (an unclosed or nested comment, a character no token takes, a product with two `/`), as before. Known false negatives, kept on purpose: a comment's entries after its `Android` entry name the device, which no vocabulary can list, so a token placed there is read past and the value stays unpublished; and a bare two-letter word that is an ISO 639-1 language code is read as a locale, since refusing it would publish real browsers' headers. The reading is one pass over the text. Follow-up: a Suricata rule for such a user agent is a separate change.
