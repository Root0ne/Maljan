### Security

- **A backslash before a letter in the password of an address written with no scheme no longer keeps it unmasked (T-423).** Any backslash before the `@` that escaped neither a quote nor a backslash read as a Windows path's separator, so a password JSON text escapes (`{"password":"p\\ss@h:8080"}`, `user:p\\ss@h:8080`, `user:pw\nx@h:8080/v1`) or one written with a backslash (`p\ss@h:8080`) was kept whole, and a path anywhere earlier in the same word (`{"a":"C:\\x","b":"p\\ss@h:8080"}`) shielded the password after it. A backslash now marks a path only where what stands before the `@`, after the last character no Windows path holds (`"`, `<`, `>`, `|`), begins as a path does: a drive (`C:\`), a UNC share with its server's host name (`\\srv\`), a long-path or device prefix (`\\?\`, `\\.\`), a relative path (`.\`, `..\`) or an environment variable (`%ProgramFiles(x86)%\`, `$env:APPDATA\`); a drive written with a slash and a name after it (`C:/Users/bob\x`) only at the start. It begins the word or a quoted value (`path:'C:\x@h/y'`), or follows `=`, `,`, `;`, a single quote or an opening bracket with no `:` before it in the value, so `--out=C:\x@h:8080` is kept while `u:Xy;\\9k@h:8080` and `{"password":"Xy,\\9k@h:8080"}` are masked; a JSON-escaped quote never opens a path (`{"password":"Xy\"C:\\k@h:8080"}` is masked), and a path that ends before an opener shields nothing after it (`.\x('tok\q@h:8080')` is masked). `C:\Users\bob@h:8080`, `\\srv\share\bob@h:8080`, `\\?\UNC\srv\x@h/y`, `{"path":"C:\\Users\\bob@h:8080"}` and their JSON-escaped forms are kept as before; a rooted path (`\Windows\x@h:8080`), one behind a colon and a backslashed word with no such start before a port or a path (`dir\a@h:8080`) are now masked. Before a mail address's host any backslash still refuses the reading. The event scrub registers each run between backslashes, openers and colons that has a token's shape, so the password is registered as written unescaped too; a domain account (`CORP\Administrator@dc01:389`) registers nothing.
- **An address inside JSON text that is itself a JSON string value is masked.** A bare host followed by an escaped quote (`{"a":"{\"password\":\"pss@h:8080\"}"}`) did not read as the end of an address, so the whole value was kept; a backslash before a closing quote now trails a bare host as the quote does.
