### Security

- **The object store's bucket is left private, checked, and not used while anyone can read it (T-575).** Every new bucket was meant to get an anonymous-deny policy, but MinIO refuses its `aws:PrincipalType` condition (`MalformedPolicy`), so the call only logged a warning and no bucket carried it. A bucket with no policy is how MinIO refuses an anonymous caller (checked live: an anonymous read, write, listing and bucket HEAD are refused, the platform's keys work), so a fresh bucket now gets no policy and the log says so. Whether the bucket is private is asked at start, by `/health?deep=true` and before a sample or a sandbox report is stored or served, at most once a minute: an anonymous client, bounded to two seconds and never retried, lists the bucket and reads a key that is never written, and the bucket policy is read for any statement open to anyone (`*` anywhere in its principal, a `NotPrincipal`, a `NotAction`). While it lets an anonymous caller in, the API log names what it allows at ERROR, the health check answers `degraded` with only "object store policy check failed", and the sample upload, the worker's sample download, the evidence download and a sandbox report's write and read answer 503 "object store is not private; see the API log", until the store is fixed; the API still starts. A key that may not read the policy leaves an anonymous write unchecked and says so once.
- **The MinIO container runs with no Linux capability and no way to gain one.** The `minio` service drops every capability and sets `no-new-privileges`; it starts, stays healthy and reads and writes an existing `minio_data` volume with them. It still runs as root, which owns that volume.
