### Security

- **Text shown for display is masked by every secret value the platform holds, in each encoded form (T-482).** The masking (`maljan.core.settings_masking`) found a credential by where it stands, so a password after a path, beside a UNC share or behind a JSON escape was kept wherever no rule read its place (`C:\x=u:pss@h:8080`, `u:pss@h:8080,x`, `x;u:p\q@h`, `u:/p\x@h`, `\\pss@SSL\x@h:8080`). Now, after those rules, every value the settings hold is masked wherever it appears in the console's read, the export, `redact_url` and the error texts of tool servers, sample staging, the system checks and the provider readiness (`masked_values`): the credential fields (`SecretStr` and the names the catalogue reads as a credential), a tool server's `env` entry whose name names a credential, a source's own credential, the value of every encrypted settings row other than a server's `env` row, the password and credential query values of every stored address and its `user:password` userinfo whole (`settings_catalog.shown_secret_values`). Each is found as written, URL-encoded (`quote`, `quote_plus`, either case of escape), JSON-escaped once and twice, and base64-encoded (standard and URL-safe, padded or not, at any of the three offsets inside longer base64, so `Basic <user:pw>` is found from the password alone). Overlapping values are masked as one run, and a source probe's own credential is masked in the same pass, so a short credential and a held value never split each other. A value shorter than eight characters (the event scrub's floor) is masked only by the structural rules. One pass, linear in the text: a trie pattern, and an automaton for a set nested deeper than the regex engine compiles. The values are registered by scope where settings are read in force (an app, a worker, a job, the store read or saved and before the console's read, the console's cached settings on each rebuild), and only counts are logged; with several processes, one masks a newly saved secret by value from its next read of the store. The run snapshot, the efficiency fingerprint and the disclosure's hosts are records and keep the structural rules alone (`by_value=False`), unchanged. The structural rules run first and are unchanged, so nothing masked before is kept now.
