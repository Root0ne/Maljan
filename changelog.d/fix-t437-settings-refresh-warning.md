### Fixed

- **A failing read of the stored settings is said once, not every five seconds (T-437).** The API reads the servers' kept declarations and the stored settings its built-in servers are read through at most every five seconds, on the requests that need them; when that read failed, it logged the same warning at every such request. It is now said once per distinct failure (which read, and the error's type), the reading before it stays in force, a read that succeeds again says so, and the failure in force is on the system status for an admin caller (`served_declarations_unread`), omitted when the last read succeeded. A database that cannot be read for the kept declarations is such a failure too, and a second outage after a recovery is said again, where it was said once per process before.
