### Fixed

- **The analysts and the judge are told when an attached sandbox report names another target (T-514).** An attached report's target hash was compared with the sample only at its upload (`sample_sha256_match`), and the run recorded a mismatch only as a degradation reason, so the analysts and the judge read its behaviour as the sample's without being told. The run now marks an attached report as it marks a live one (T-322): from the target hash the report's reader put in the neutral report, whichever format it was accepted as, and the pack's `sandbox_status` step states it before the sandbox views in the same sentence, with the same code spans and cleaning. A block the uploaded document carried under the mark's word is taken out with a warning, or replaced by the run's mark. The worker records it as it records a live one's: the run summary's `sandbox_target` record and the disclosure line naming both hashes, beside the upload's own degradation reason. An attached report whose target is the sample, or that names none, is handed on unchanged, byte for byte.
