### Security

- **A credential no setting holds is masked in shown text whatever stands around it (T-481).** The structural masking kept a user name and password written with no scheme in a few shapes: after a path that ends in `=`, a closer or a bracket rather than `,` or `;` (`C:\x=u:pw@h:8080`, `C:\x)u:pw@h:8080`, `[C:\x]u:pw@h:8080`), when anything followed the host in the same word (`u:pw@h:8080,x`, `C:\x,u:pw@h:8080,C:\z`, a JSON member after it), behind the doubled backslashes JSON text inside a JSON string writes before a quote, and a password holding a backslash before a host with no port or path (`x;u:p\q@h`). A path now also ends at `=` and at a closer, the address ends at a separator, closer or quote after its host and at any character but a letter or digit after its port (`u:pw@h:8080|jq`, `u:pw@h:8080=x`), a quote may stand behind any run of backslashes, and before a host with no port or path a backslash keeps the address only where it escapes a quote (a mail address's quoted name in JSON) or a path begins in it. Each new reading only adds masking: every reading masked before is masked from where it was, the event scrub registers the same credentials and more, and paths, Windows paths, mail addresses without credentials, URLs without userinfo and version strings read exactly as before. The cost stays linear in the text.
