### Changed

- **Enrichment asks a reputation server's indicator lookups, and its credential settings come from the source declarations (T-418).** The settings catalog no longer holds a table of the shipped enrichment sources' keys: each shipped declaration's `credential` generates its secret setting, titled by the source's label, described by the indicator kinds that leave the host and the host they go to, and tested by the source's own declared `probe` (the shipped two keep `api.virustotal_api_key` and `api.abuseipdb_api_key`, their titles and their Test buttons). Their descriptions no longer say that the threat-intel sidecar reads them, which it never did: it reads its own environment. A server source may now name no `tool`: it is then asked through the server's indicator lookup for each kind, the first tool its `tools` list ticks whose declaration in force (the block's, the server's own, or what is read of its listing) is a lookup about an indicator and names an argument for the kind, never one that sends the sample. A server source that declares no `record` reads the answer as a reputation answer, through the tool's declared paths or else by its shape, into `malicious`, `suspicious`, `total`, `engines`, `labels`, `first_seen`, `last_seen`, `link` and `service`, each only where the answer gave it, and its `malicious_when` may name the four counts. A report on an indicator read from a reputation server's listing now names the argument it requires each domain, address or URL in, so the disclosure counts which indicators a call carried. The new switch `api.enrichment_reputation_servers` (off by default, the operator's consent) makes every enabled server whose `roles` hold `reputation`, and that no source names, a source under `mcp:<key>`, ordered by its `reputation_service.rank`, paced by the new `reputation_service.rate_limit_seconds` (where the block says none, the slowest pace a shipped source declares, 16 s today) and judged by the new `reputation_service.malicious_when` (where the block says none, its records carry no verdict and mark no indicator); a lookup that fails is followed by the server's next one, and a lookup whose listing requires another argument, or is read as sending the sample whatever its declaration says, is never asked; the run's disclosure names each such server before the first question and counts every question asked. The shipped REST sources make the same calls and store the same records: re-enriching every stored run's indicators under a fixed answer gives the same 231 records, field for field (0 differences), and every stored run replays as on `origin/dev`.
