### Fixed

- **A job's usage and its live conversation name the model that answered instead of `***`.** The event publisher read `anthropic/claude-haiku-5-5` as a key by its shape (26 characters of the base64 alphabet with digit pieces), so every `model_usage` row and every streamed turn of an Anthropic run carried `***` as its model, and `GET /api/v1/jobs/{job_id}/usage` counted each agent's calls under no model. A model field (`model`, `models` and the keys of a per-model tally) is now scrubbed as a model label: configured secret values are masked and a URL loses its userinfo and credential-named query values; then each side of ` @ ` is kept as written only when it is an endpoint label (a scheme and a host) or `provider/model` written as a model id is — words in one case, numbers of up to eight digits, fewer than three short letter-and-digit runs in one case, no vendor key prefix — and is given the whole scrub otherwise, so `anthropic/sk-ant-…`, an AWS key id and a mixed-case or grouped key are masked as before. The fields that name an agent, a stage, a server or a label now also mask a configured secret value, a short one as a whole word.
- What stays as it was, or is the stated cost: a model id of at least 24 characters that passes the model-id rule travels as written although the whole scrub masked it — `claude-sonnet-4-20250514` is the intended case, and an unconfigured secret written the same way (lowercase words, numbers and at most two short letter-and-digit groups, such as `abcdef-123456-ghijkl-789012`) passes with it; configure it as a secret and it is masked by value. A passphrase of words passes, as it did. A process that has registered no configured values, or whose registration failed, holds a model label to the whole scrub, and the API process registers none, so a follow-up's usage rows can still read `***`. A model name inside prose (a reason, a report) is judged by the shape rules as before. Rows already stored keep `***`.
