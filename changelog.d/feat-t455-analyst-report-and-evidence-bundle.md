### Changed

- **The served report is an analyst report, with the record behind it in an evidence bundle beside it (T-455).** The Markdown, HTML and PDF exports printed every tool table, the run's bookkeeping, the full ATT&CK and indicator tables, the limitations ledger and the evidence appendix in one file of up to 100,000 words, with a citation after nearly every sentence. They now print the findings in a fixed order: title block, executive summary, introduction and scope, sample metadata, execution flow, functionality, command and control, conclusion, detection (indicator table of type, value and role with links to the STIX, indicator and MISP outputs; drafted rules with what checking them against the sample found; hunting guidance), recommendations, a compact ATT&CK table (tactic, id, technique, one-sentence procedure) of the published techniques, a short limitations paragraph, and an appendix with the rule bodies, the analysts' statements that add a value printed nowhere else, and the references. Each citation is a numbered note (a superscript link in HTML and PDF) and each section ends with links into the evidence bundle. Selection is by the kind of each block and its published state, never by a tool or a family. The model's prose is printed as written, defanged, with only its citations moved; confidence numbers the platform printed are words. Every caveat the single-file report prints beside a finding stays: the marks of sentences a check left standing, the unresolved findings on the verdict and the summary, the flow, configuration and identifier marks, a family grounded on nothing, the status of a published technique only a rule matched, each technique named and not published with its reason, and the publish rule's answer beside every indicator the run does not export. The PDF reads alone: it ends with its notes and their evidence ids and says where the bundle is (beside the downloaded report, or the API path, which requires sign-in), with no link built from the request. On the stored runs the analyst report is 4,800 to 18,600 words, against 23,000 to 102,000 for the single-file report.

### Added

- **The evidence bundle, `evidence-bundle.html` and `evidence-bundle.json` (T-455).** It prints every section the single-file report printed, as it printed it, and the notes the analyst report cites, each listing its evidence ids linked to their rows in the evidence index; every evidence id, note and section the analyst report links to has an anchor. It is served at `/reports/{id}/evidence-bundle.html` and `/reports/{id}/evidence-bundle.json`, so the analyst report's relative links resolve from `/reports/{id}/html`, and written beside the report in the job package (`report/`) and by the command line, under exactly those names. The console's Export menu offers both in its Deep group, saved under the same names, and the report's HTML item says to save the bundle beside it; a menu taller than the window now scrolls, so its last items stay reachable. The benchmark's provenance pass reads a numbered note back to its evidence ids through `evidence-bundle.json`, and the surface checker reads the report and its bundle together. Over every stored run the analyst report and the bundle together hold every value, claim, citation id, technique, indicator and limitation reason the single-file report held, and every scored quote of the haiku6 and haiku7 scores is in the analyst report.
- **`reporting.full_report_in_one_file` (default off).** On, the served Markdown, HTML and PDF print the single-file report as before; the bundle is still served. A render-time choice: nothing stored changes, and the STIX, indicator, MISP and rule outputs are the same either way.
