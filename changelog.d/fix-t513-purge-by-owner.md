### Added

- **An admin purges long-term memory by owner prefix (T-513).** Memory a job files under an owner key of its own, below its account's (`<account>/job/<job id>`), is read by nothing again. `POST /system/ltm/purge-owners` (`{"owner_prefix": ..., "dry_run": ...}`, admin, like the low-quality purge) removes every case and function hash filed under an owner at or below the prefix, from the in-memory store, from Qdrant and from the function-hash collection beside it, and answers the counts per kind; a dry run counts and removes nothing. The prefix is read a path segment at a time (`long_term_memory.owner_under`): `<uid>/job/` names that account's job memory and never the account's own, `<uid>/jobs`, another account whose id begins with the same characters, or an unscoped entry. A prefix that names no owner path and a backend that cannot purge by owner are refused. A purge leaves an `ltm.purge` audit row with the prefix and the counts, and one that fails part way leaves `outcome=failed` with the error class and what the store lost; a failure is raised, never answered as 0. No schema change.
