### Changed

- **Every tool server can declare its own tools, read as far as its block trusts it, and the platform's sidecars do (T-418).** A tool's facts (its kind, where its answer's rows, places and values sit, the techniques it names, the formats it serves, what it shows and does not show, what a call does beyond answering, its budget) were known only from what an operator stored or what the platform shipped for a built-in server by name. A server now says them itself when it lists its tools: MCP annotations (a title, and the read-only, idempotent, destructive and open-world hints) and, under the tool's `_meta` at `maljan/tool_facts`, a declaration in the vocabulary of `tool_facts`. The client reads it for every server alike when it attaches one, keeps it under the launch identity of the block that reached the server, and reads it by the block's new `trusts_served_declaration` (in the settings catalogue and the console's Declaration section). A block that trusts it reads it as a declaration under its own, per tool and field by field: what an operator stored (or the platform ships) is in force over the server's, and a built-in tool an operator removed stays removed. Any other block reads only the claims that make the platform more careful (it sends the sample or its hash out, reaches the network, runs something, or is not read-only) and stores each such field with the tool's entries as the server's own statement, which the tool-effects part says as such, which never moves a call to another disclosure row and which no reader of a stored entry reads as declared. Such a server's kind is never put in force: a kind whose answer moves or that reaches outside (never a reputation kind) is stored apart as its claim, said as the server's, and read only to keep an identical call from being answered again from the job's ledger. The connection test proposes the rest, the kind included, with medium confidence as the server's own claim (high for a block that trusts it), never less careful than the tool's hints. No block takes a kind of what a sandbox observed from a server unless its roles hold `sandbox`. All twelve sidecars under `services/` (analysis, knowledge, network, threat intel, Detect It Easy, ILSpy, GoReSym, YARA-X, oletools, webcrack, unblob, JADX) declare their 81 tools so and ship trusted (a trust that holds only while the block still reaches the server it shipped with, unless the operator sets it), and a test holds what each declares equal, field by field, to what the platform read for it before (0 differences over 81 tools), against a capture that is never regenerated. The call guard's budgets and long-running flags, the description tags and the prompts' known tool names read a server's declaration from its attach on; the static pre-pass's tool choice, the triage pack's server choices and a Ghidra block's own reads still read the block alone. A run's recorded declaration digests are of the blocks alone, and each server's declaration is recorded by its own digest beside the version it gave. The shipped per-tool tables of those servers stay for now: the API, a render, a replay and agent composition read them without attaching any server, so taking them out first needs a reading of a server's declaration that outlives its attach. Every fact a run reads is unchanged: a deterministic triage pack run and each sidecar tool's stored facts record read the same with and without the servers' declarations (0 differences), and every stored benchmark run replays as before. The servers' new hints are kept on their tools' ledger entries, so a tool its server marks read-only and idempotent may be answered again from the job's ledger.
