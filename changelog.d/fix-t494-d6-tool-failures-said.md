### Fixed

- **A failed tool call a later call redid is no longer said as a gap in the evidence (T-494 D6).** The report said "The evidence is partial: 5 of 214 tool calls failed" in its header and its limitations while three of the five had been asked again and answered for the same addresses, and the limitations paragraph then said the reversing tools failed. A failed call is redone when a later call answered for every address it was asked for, by the link the agreement question already reads (the same tool, or for a call that lists code, any later listing of that function; a listing that is error text answers nothing). A call asked for no address is never redone: another call of its tool with other arguments answers another question. The run summary's `evidence.failed` still counts every failed call, and `evidence.redone` lists each redone one with the calls that answered it (absent when none). The partial-evidence sentence counts only the failures no later call redid ("2 of 214 tool calls failed and were not redone"), and says nothing of failures when every one was redone; the report header's evidence line and the evidence bundle's bounds say how many failed calls were redone, the bundle with each failed entry and the entries that answered it. The limitations paragraph is shown each redone call as a fact (`failed_calls_redone`), its ids readable. A run with no redone call reads and is asked exactly as before.
