### Fixed

- **A failed tool call a later call redid is no longer said as a gap in the evidence (T-494 D6).** The report said "The evidence is partial: 5 of 214 tool calls failed" in its header and its limitations while three of the five had been asked again and answered for the same addresses, and the limitations paragraph then said the reversing tools failed. A failed call is redone when, for every address it was asked for (read as the agreement question reads them), a later call answered the same question: a call of the same tool whose every other argument is the failed call's, except one absent or null on either side and one whose failed value the failure's own message names; or, for a failed call that lists code, a call of another tool that lists that function whole (a decompiled listing holding it, or a disassembly of the whole function; a read of some instructions from the address is not one). The answering call must hold its answer, and a listing that is error text answers nothing. A call asked for no address is never redone. The run summary's `evidence.failed` still counts every failed call, and `evidence.redone` lists each redone one with the calls that answered it (absent when none). The partial-evidence sentence counts only the failures no later call redid ("2 of 214 tool calls failed and were not redone"), and says nothing of failures when every one was redone; the report header's evidence line, the evidence bundle's bounds and the console's run-quality card say how many failed calls were redone, the bundle with each failed entry and the entries that answered it. The limitations paragraph is shown each redone call as a fact (`failed_calls_redone`): the entry ids alone, readable. A run with no redone call reads and is asked exactly as before. `agreement_facts` exports the address readers it used privately (`asked_addresses`, `answered_addresses`).
