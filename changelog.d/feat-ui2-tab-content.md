### Changed

- **Behaviour, Network, Static & code and Indicators & detection are redesigned around what a reader picks first (T-465).** Details open in the side panel instead of a third level of nesting, long lists are drawn ten rows at a time with "show more", every block keeps its place and says "Not found" when the run left it empty, and block titles are plain words rather than capitals or section keys. **Behaviour** leads with the process tree: the sample's path (a process the sandbox marks as the sample's, one that injects, or one whose pid another part of the report ties to a DNS query or a registry write, with its ancestors and the processes it started) is open and marked, the other processes fold into one "N other processes" row, the tree draws twenty-five rows before offering more, and a process opens its full command line and why it is on the path. Behaviours list the sandbox signatures by severity on the one n/5 scale (the sandbox's own number beside it) and then by ATT&CK technique, each opening its evidence marks — all of them, where the old list stopped at twenty-five; then the persistence mechanisms, and the registry, file and API activity as tables (the registry table pages instead of stopping at 200 rows, and the file and API records are columns instead of raw JSON). ATT&CK is a compact tactic-to-technique list with id chips and counts, a technique opening its sources and corroboration, and the full matrix behind a "List / Matrix" toggle. Persistence and defence evasion are views of the tab ("All behaviour · Persistence · Defence evasion"), read from the run's own technique-to-tactic mapping, and the old `/persistence` link opens the persistence view. **Network** keeps its counts (now with TLS fingerprints) and the enrichment button, then lists every host with its reputation and whether it was looked up, a host opening what is known about it and the requests it received; the HTTP requests, DNS answers and TLS and client fingerprints are tables of their own, a request opening its method, status, user agent and source; the endpoints found only in the sample's strings follow. **Static & code** groups identity, metadata, packing and build facts and the hashes; the file's structure is one vertical sub-tab at a time, reached with the arrow keys as tabs are (sections, imports with the ATT&CK-from-imports table and the import capability profile, exports, and resources, where every embedded resource is listed and the carved ones flagged, with a note at the top when any was carved); strings have a search and kind facets with counts; the recovered configuration has its own block with a copy per value, and is drawn only there and in the Overview summary — the technical analysis on Behaviour links to it instead of repeating the table, and the block is drawn even on a run with no static block; and the functions examined, with any decompiled excerpt, have theirs. **Indicators & detection** is one indicator browser — type facets with counts, a search, an export-decision filter (published, withheld, no answer recorded, or a value only the verdict names, each counted on its own), a copy control on every value, and a side panel with the publish decision and its reason, whether the verdict names it, and the related findings elsewhere in the report — then the rules that fired, the generated rules as one list with a copy and a download per rule and the body in the side panel, the STIX objects drawn on request, and attribution. The typed process tree, signatures and network tables are drawn even where a sandbox section lists the same rows, which stay one click away beside them with their citation marks; the classified strings are drawn beside the printable-strings section rather than replaced by it. Section keys are printed only under Evidence. Console only; no report, API or stored run changes.
