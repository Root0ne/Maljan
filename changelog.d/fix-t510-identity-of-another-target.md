### Fixed

- **The judge is never given another target's md5, sha1 or size as the sample's (T-510).** The judge's sample identity block took the md5, sha1 and size from the sandbox report's own file block, as facts about the sample with no caveat, also where the run had marked the report as naming a target that is not the sample (T-322). A marked report's file block is now left out of the identity, and the md5, sha1 and size are read from the sample's own bytes in one pass, given only where that pass still reads the intake SHA-256; a copy that is not the intake bytes, or none on disk, gives no hash. An unmarked report gives the judge the same block, byte for byte.
- **A marked run's identity block says where its values came from, and reads the copy once (T-510).** The judge's block on a run whose sandbox named another target is headed as established by the router and the sample's own bytes, not the sandbox's file block, where the bytes gave its rows; a block they gave no row keeps the router's header, and an unmarked block keeps its header, byte for byte. Where the copy no longer reads the intake SHA-256, no size is taken from it either. The copy is read once while its size and modification time hold, however many judge turns build the block, and no further than the intake size where it is given.
- **A run whose sandbox named another target is routed by the sample alone (T-510).** The file type and platform the analysis is routed by took the sandbox's file type and guest system as a hint about the sample, also where the report named another target. On such a run only the sample's own bytes are read, and a warning in the run's log says so; an unmarked report routes as before.
