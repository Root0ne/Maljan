### Added

- **Container and Android servers: unblob and JADX, one container each, with their own pack steps (X28, X31).** Two more built-in server blocks ship switched off, over the shared `services/cli-sidecar` plumbing as the identification and document servers are: `unblob` (unblob 26.6.4 with the extractors it calls: `container_scan`, each chunk of a known format inside a file, found by its own bytes, with its byte range and the unclaimed ranges' entropy; `container_extract`, every file a container or firmware image holds, extracted recursively, each with its size, sha256 and file type, links by what they name and what unblob refused) and `jadx` (JADX 1.5.6 on Java 21: `android_classes`, the classes of an APK or dex file with their methods; `android_decompile_class`, one class as Java), each with a `capabilities` tool. Neither runs what it reads. unblob writes what it extracts into a directory of its own per call under its container's tmpfs (`UNBLOB_CARVE_ROOT`, `/tmp/carved`), never beside the sample, which stays mounted read-only; unblob refuses a member whose path or link leaves the extraction and a device file, the listing walks the directory by its bytes without following a link (a link is listed by its target, a FIFO by its kind, neither opened; a name that is not UTF-8 shown with its bytes escaped and handed on percent-encoded). Each run is held to machine-safety bounds, each the operator's to set: it stops once the files written pass the larger of the sample's size and the platform's sample upload bound (`UPLOAD_MAX_BYTES`, 100 MiB unless set) or once it made more than `UNBLOB_MAX_ENTRIES` entries (100,000 unless set), counted at once and then twice a second, and then lists only the files that fit under the bound and says so in `stopped`; no one file it writes may pass that byte bound (a file cut there is named, not handed on); and its `/tmp` is a tmpfs of its own sized below its memory ceiling (`UNBLOB_TMPFS_SIZE`, 1536m), so a run that writes past the last count fills the file system, not the memory. Each extraction's directory goes `CARVED_KEEP_SECONDS` after its writing ended (an hour unless set), the oldest first when a new run would not fit. A file it wrote reaches another server only through the job's artefact store: the shipped step declares `outputs` `/files/*/path`, and the store reads each file back over the server's `get_artefact`, which opens it beneath the carve root with no link followed, refuses anything but a regular file and answers at most 4 MiB a call; a file of several names (a busybox link farm) is handed on once, under one name with the others in `also_named`, only when every name is inside the same extraction; `get_artefact` is a delivery primitive no model is shown. JADX is handed the file under a name of the server's choosing (`input.apk` or `input.dex`, by its first bytes), with every input plugin but the dex reader switched off, no configuration file read, no resource decoded, its temporary files and home in the call's scratch and no comment of its own in the code, so one file answers the same each time; its heap is half the container's memory, beside a `/tmp` tmpfs sized below the rest (`JADX_TMPFS_SIZE`, 1536m); the manifest, permissions and certificates stay `apk_info`'s, which androguard reads as before. Each image pins its program by version and checksum (sasquatch's Debian package, the Temurin 21 runtime's archive and JADX's release archive by the sha256 GitHub publishes) and unblob's Python packages by hash, wheels only, at the MCP SDK versions every sidecar pins (setuptools at 84.1.0, past GHSA-xmj3-9gf7-h52w). The compose file adds each under its own profile (`unblob`, `jadx`) under the `x-cli-sidecar` anchor, with a memory-and-swap ceiling (`UNBLOB_MEM_LIMIT` 2g, `JADX_MEM_LIMIT` 4g), an internal network of its own and a bare relay (`unblob-port` 8096, `jadx-port` 8097); `unblob` is offered to the static analyst and the reverser, `jadx` to the Android static analyst and the reverser. Two shipped pack steps, each off (no call, no entry) while its server is not switched on, run after the document steps: `container_extract` on every sample and `android_classes` on `apk` and `dex`. Dependabot keeps `services/unblob-mcp` current. A deployment without the servers runs the pack as before, and stored runs replay identically. Not shipped: binwalk (unblob covers the same formats with the same extractors, and binwalk 3 publishes no release binary to pin), a shortcut's own fields, and a FLIRT or BinDiff server: capa's FLIRT signatures already name a PE's library functions in `capa`'s answer, and a BinDiff comparison needs a disassembler's export of each input and a second sample a run does not have.
