### Fixed

- **MinIO is built from source, so a clean stack starts again (T-572).** The `minio/minio` image compose pulled is no longer served by its registry, so a `docker compose up` on a host without it cached stopped at MinIO. Compose now builds `maljan-minio:RELEASE.2025-10-15T17-29-55Z` from `docker/Dockerfile.minio`: the upstream release tag is cloned and must be its pinned commit, compiled with Go 1.27, a supported release above the Go 1.24 floor its `go.mod` names (cross-compiled for amd64 or arm64 by the target's architecture), and copied with its licence onto a digest-pinned Alpine image. The service keeps its name, container name, command, ports, credentials and `minio_data` volume, so the API's client and the audit anchor's object lock read it unchanged. The healthcheck asks `/minio/health/live` with the image's `wget`, since the image carries no `mc`. The server still runs as root, as the pulled image did, because an existing volume holds files root wrote. A test holds the image tag, the release and the commit together, and Dependabot offers each newer Go below a major.

### Upgrading

- **The first `up` after this builds the MinIO image and reuses the existing volume.** The release built is the one after RELEASE.2025-09-07T16-13-09Z and changes no on-disk format: buckets, objects, versions, policies and object lock settings written by the pulled image read as before. The build needs network access to GitHub and the Go module proxy. MinIO is AGPLv3; the repository ships the Dockerfile, which builds the unmodified upstream source (see *MinIO, built from source* in the deployment docs).
