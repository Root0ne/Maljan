### Security

- **A console trust grant holds for the launch as the server is started, the files it resolves to included (T-432).** The trust an operator grants a server's own declaration from the console (`trust_granted_for`) was recorded against the block's launch fields as written, so pointing a symlinked command, a relative command's working directory, an interpreter's script link, `PATH` or the child's environment at another program kept the grant. The grant's digest (`granted_launch`) now also holds the block's `env_allow` and its own `env` (each value by its digest, never in the clear), so a changed `PATH`, `LD_PRELOAD`, `PYTHONPATH` or `NODE_OPTIONS` withdraws it, and, for a stdio block, what its launch resolves to, read by the one helper the launch itself uses (`subprocess_env.stdio_launch`): the real working directory, rooted at the project as the launch roots it; the real file the command runs (a path, relative ones read from that directory, or a bare name found on the `PATH` the child is given); and the real path of each argument, as the launch roots it, written as a path that exists, or of an option's value after `=` that does (`--script=./x.py`). Where a stdio command or working directory does not resolve, no grant is recorded and none recorded before holds. Where the server is started, a block whose launch no longer matches its grant does not trust its server's declaration, and the worker says so. No release is read and a file replaced in place keeps its path, so a grant still survives an upgrade. A block that reaches its server by address reads as before. The enrichment worker now mounts the same trees as the API and the analysis worker (`data`, `tests` and `services` read-only beside `src` and `apps`), so a grant recorded by the API resolves alike where the enrichment worker starts the server; a guard test holds every backend service that starts stdio servers to the same mounted trees in each compose file. A grant recorded by the previous digest for a stdio block, or for any block with an `env` or `env_allow`, is read as another launch's, so its trust is withdrawn once and must be granted again.
