### Fixed

- **A command table's ids are checked against the values the code it was shown compares (T-378).** The `commands` section was shown a decompiled dispatcher whole, as code only, with the one-line instruction "Extract the commands the sample accepts from its operator", and nothing compared the table it wrote with that code. On a stored run the writer turned the hex case values into decimal ids by hand: case 0x15 came out as row "18", cases 0x11 and 0x12 had no row, and case 0xf was described from an analyst claim rather than its branch. Under each piece of code a section is shown whole, the platform now states each expression the code chooses among two or more whole numbers by (a switch's case labels, and an else-if ladder whose rungs test one name for equality, alone or joined by `||`), one function apart from another, with every other equality test of that name in the function, every value in hex with its decimal. A set is stated whole or not at all: a case label that is not one number, a test of the name in another form (a cast, a symbol, another name), or a rung on another condition with the ladder going on after it leaves it unstated. Comments, string literals and numbers wider than 64 bits are not read, code in any other form states nothing, and a reader failure is no fact rather than a lost section. Under a captured output the lines are stated only when the output and the lines fit the output's own share of the window. A command table whose numbered ids leave out one of the values the matching expression is compared with, or name a value it is compared with nowhere, is asked about once with the values and the code in view (`composer.command_values`); the model decides which value is a command and what its branch does, and a table kept as written stands with the finding beside it. The instruction now asks for each command's branch value as its id, in one base for every row, and for what that branch's own code does. A table whose ids are 1 to N, which row numbers would be too, is not checked. On the stored run the commands prompt grows by 215 characters and the question names 0x11 (17) and 0x15 (21); a run whose table already names every value (or whose ids are not numbers) is not asked.
