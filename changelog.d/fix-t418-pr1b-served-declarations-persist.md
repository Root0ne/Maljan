### Changed

- **What each tool server declares of its own tools is kept past the process, and the platform ships no table of its own sidecars' tools (T-418).** A server's declaration of its tools (its `_meta` at `maljan/tool_facts`, read by its block's `trusts_served_declaration`) was read only after it attached, so the readers that decide before any attach (the triage pack's servers, steps and readings, the reputation lookups and their order, the routed formats, the servers a capability binds, the static pre-pass, the check of a pack step's kind) read the twelve sidecars' per-tool tables the platform shipped instead. Each source's last declaration is now kept in the database (`served_tool_declarations`, one row per source, under the launch identity of the block that reached it; a new migration), read by the worker at each job's start and by the API before it answers, and written back after each job and connection test; a block whose launch identity changes forgets it. Every reader above reads the declarations in force through it, and the twelve tables are gone: what the platform reads of its sidecars is what each serves. A command is read as the file it runs, so `bin/python` and its link `bin/python3` in one directory are one launch (a stored block naming the other spelling keeps its trust), and links to different programs stay two. On a fresh install, before a server's first listing, it is read as any undeclared server is and nothing is refused for it; a job that runs for real (never a mock run) lists each enabled server whose block trusts its declaration and for which nothing is kept (a handshake, no tool called, at most four at a time, within thirty seconds), so the first run reads what every later one reads; one that cannot be listed, or declares nothing, is not reached early again for ten minutes. A built-in block pointed elsewhere and trusting its server is read through that block by every reader, and a row listed through a server's shipped launch is read under the reading host's own shipped launch. A built-in block pointed at its sidecar's own container needs `trusts_served_declaration` set, as the compose file now says. Every fact a run reads is unchanged: a deterministic triage pack run's ledger facts and every config-time reading are the same as before (0 differences), each sidecar still declares what the platform read for it (0 differences over 81 tools), and every stored run replays as before. The zero-cost rehearsal's gate keeps a tool server on only where its declarations in force say it makes no outward call; one whose effects are not known (wholly or for some tools, a server never listed among them) is now switched off and named, where it was kept, and the stack's own servers this machine reaches are listed first, as a job lists them.
