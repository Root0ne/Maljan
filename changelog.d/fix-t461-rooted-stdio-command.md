### Fixed

- **A stdio tool server's relative command runs the project's file, whatever directory the backend was started in (T-461).** A block with no working directory of its own had its arguments rooted at the project but its command started as written, so `bin/server` ran from the API's or the worker's own directory, and a console trust grant could hold for a different file than the one a worker started. The command is now rooted at the project when its first component past any leading `./` exists there and the rooted path stays inside the project (`\` is a separator only on Windows), and the launch and the trust grant read that one rooted command. The Ghidra provider's local launch now reads the same launch as every other stdio server (its command, arguments, environment and working directory), so it starts what its grant holds for. A bare program name such as `npx` or `uvx`, an absolute path, a path that leaves the project (`../x`, `./../x`) or names nothing in it, and a relative command beside a block's working directory (run from that directory) are started as before, and a grant recorded for any of them still holds.
