### Fixed

- **An ATT&CK procedure is asked only for the values of its own technique's behaviour (T-495).** The check that a one-sentence procedure keeps what its claim shows compared it with the first sentence of the technique's first claim, and asked for every value in it. That sentence often describes something else (the command runner several discovery techniques share, a Desktop listing before the process listing), so a retry pulled off-topic values into procedures: T1057 led with the Desktop listing, T1105 and T1106 became the same sentence, and section names such as `.text` were asked for. Each claim of the technique is now read as the parts that name its technique: the sentence or list item naming the technique id (not a remark that names other published techniques too), else the clauses naming words of the technique's name, matched as whole words from their first letter with an identifier read by its humps (`GetUserNameA` names "user"; `Toolhelp32` is no "tool", "procedure" no "process"), else the first sentence that says no "not". A part that says the behaviour is not so ("does not delete itself", "was not run") is used only when no other part qualifies. The procedure stands when it carries every identifying value of one claim's part, each claim read as the part it shares most with; otherwise it is asked for what it drops of the part it shares most with. A section name or extension and its dotless twin (`.UPX0`, `UPX0`) and an argument name (`arg2`) are never asked for, and a one-byte constant only when it is the part's one identifying value (an XOR key). On the stored haiku8 first answer, the check raises 8 findings instead of 16.
