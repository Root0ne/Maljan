### Fixed

- **The IOC table, `/iocs`, the STIX export and the MISP attributes carry one decision for every indicator (T-344, T-345, T-351).** `/iocs?include=all` was a subset of the report's IOC table: a dropped file's digest, a spawned command line and every path, registry, mutex and service row had no row in the feed, and those rows carried no publish answer, so the surfaces could not agree on them. Every row of the table is now asked the one publish rule under the source that recorded it. A digest, path, key or mutex the sandbox recorded is published only when its record names a process of the sample's process tree, as a sandbox flow is, and is otherwise withheld with the reason, unless the judge kept it when asked with that fact, as for a sandbox flow (the row's own sandbox record is never its second source); a persistence record's key and a static carve's digest are published; a command line, a scheduled task and a service are refused because the export has no object for them. A dropped or carved digest is typed by its length. A registry row is the key, with the values written under it in its context. The feed is built from the table itself, so the two cannot diverge, and the default `/iocs` stays the `include=all` rows marked published; when the table cannot be rebuilt and the report stored none, the feed still serves the sample's own digests. Leaked credentials and wallet addresses are served only to a `kind=secret` or `kind=crypto_wallet` filter. The export carries every observed host row the table publishes, and names the sample by its SHA-256, SHA-1, MD5 and SHA-512 in one indicator; its imphash, ssdeep and TLSH, which also match other files, are a separate `anomalous-activity` indicator. A judge indicator naming only the sample's identity digests is folded into the sample's, and the judge's bundle is no longer edited by the render. The report build now writes `misp_attributes`: one attribute per published row with MISP's standard type and category (`md5`, `sha1`, `sha256`, `imphash`, `filename`, `regkey`, `mutex`, `ip-dst`, `domain`, `url`, `user-agent` and the rest), `to_ids` from the publish decision (never for an imphash, ssdeep or TLSH) and a uuid derived from the job, then one `text` attribute per published ATT&CK technique, tagged with its galaxy cluster under ATT&CK's own name; a withheld value is never one. The console's MISP export and the job package (part `misp_attributes`) carry them. A report stored before this is served with its IOC table rebuilt and MISP attributes built when it has none, and its detail says the stored STIX bundle was rendered under the earlier rule. The surface checker now knows the DETECTION tab draws the IOC table and the judge's values.
