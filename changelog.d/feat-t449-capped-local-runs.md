### Added

- **Heavy local runs can be held to a capped systemd scope (`python scripts/dev/run_capped.py -- <command>`).** The wrapper starts the command in a transient `systemd-run --user --scope` unit, whose name it prints, with a hard memory cap, no swap, a task ceiling and a CPU quota, and a watcher stops the scope when the host's `MemAvailable` falls below a floor; when the command ends it prints the exit status, systemd's result for a failed scope and the scope's last memory events. Where the caps cannot be enforced (no `systemd-run`, no user manager, or a needed controller not delegated) it exits 2 and says why instead of running the command; `--allow-uncapped` runs it anyway and says so. Nothing runs this way unless asked: existing scripts and `make` targets are unchanged. See Development, "Heavy local runs in a capped scope".
