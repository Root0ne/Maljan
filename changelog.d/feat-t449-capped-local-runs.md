### Added

- **Heavy local runs can be held to a capped systemd scope (`python scripts/dev/run_capped.py -- <command>`).** The wrapper starts the command in a transient `systemd-run --user --scope` unit, whose name it prints, with a hard memory cap, no swap, a task ceiling and a CPU quota, and a watcher that acts only on the scope holding the command's own process reads the caps back from the scope's control group (killing a scope whose cap was accepted but not enforced) and stops the scope when the host's `MemAvailable` falls below a floor; when the command ends it prints the exit status, systemd's result for a failed scope and the memory events at the watcher's last poll. A unit name already loaded, a cap at or above the host's memory or a floor at or above what is available is refused. Where the caps cannot be enforced (no `systemd-run`, no user manager, a needed controller not delegated, or no swap accounting) it exits 2 and says why instead of running the command; `--allow-uncapped` runs it anyway and says so. Nothing runs this way unless asked: existing scripts and `make` targets are unchanged. See Development, "Heavy local runs in a capped scope".
