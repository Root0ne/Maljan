### Changed

- **An analyst that reads code is asked once about the unread functions around the routines it read (T-558).** Before its answer stands, the validation turn lists the callees of every routine a listing of the analyst holds that no listing holds, and the unread functions on the path from a stated start down to them, read from its own listings and the pack's function index. They are ranked by distance from where the code starts (the entry point and exports any format header states, the threads the function index states; where none is stated, the read routine a claim writes nearest an entry, main, dispatcher or beacon word), a further caller counting one more call so shared helpers come last. At most 12 are listed, each with its reason in addresses and counts only, and the question says how many there are. The analyst may read any of them with its tools or none; nothing is forced. The question is advisory, asked once per analyst and job, only where the turn can carry the analyst's tools, and rides the turn's other questions; `run_summary.budget.<agent>.callees_question` and an answered validation row record what it listed and what the analyst read after it. In the console the list is the agent's correction line, its reads are its own tool calls, and the line ends in a new `answered` state saying what it chose; the asynchronous retry loop publishes that state too. No agent or tool is recognised by name: whether an analyst reads code is decided in one place from the declared tool kinds, and an undeclared tool by what its name says. An analyst that reads no code is not asked and nothing is said; where the platform cannot tell, the turn cannot carry tools or the check raised, a note in the agent's conversation and `callees_question.not_run` say why, once per job. An answer with nothing unread sends what it sent before.
