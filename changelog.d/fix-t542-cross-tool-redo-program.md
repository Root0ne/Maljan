### Fixed

- **A call of another tool for another program is no redo of a failed listing (T-542).** A failed code listing counted as redone by a later call of another tool that listed the same address whole in another program, though that call answered of another file; T-529 had closed this for a call of the same tool only. A call of another tool now redoes a failed listing only when it names no other program in an argument both declare to name the program: the role `program` of each entry's stored `arguments`, which may be a different argument name on each tool. Two values name the same program when the last segments of their paths agree (`\` read as `/`), as a program argument is read where an address is checked against the loaded image, so `dropper.exe` and `/samples/job/dropper.exe` are one program; the refused program the failure's message names, replaced, is the refusal's fix. No other argument is read across tools, since another tool may give a shared name (`mode`, `format`, `timeout`) another meaning, and where either tool declares no such argument the call is read as before. A call of the same tool is read as T-529 reads it. Offline, over the stored ledgers of all 25 runs under the benchmark directory: no redone call changes (28 rows); the one cross-tool redo, run7's `disassemble_function` ev_0069 redone by the `decompile_function` ev_0123, stands, neither entry's stored record declaring a program argument.
