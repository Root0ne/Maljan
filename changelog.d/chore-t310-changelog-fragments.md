### Changed

- **A change's changelog entry is a fragment file, folded into `CHANGELOG.md` at promotion (T-310).** Every merge into `dev` edited the same Unreleased lines, so each open pull request went into conflict after each merge and its checks started again. A pull request now adds one Markdown file under `changelog.d/` (named after the branch or a slug) holding its entry under a known section (`### Added`, `### Changed`, `### Deprecated`, `### Removed`, `### Fixed`, `### Security`, `### Documentation` or `### Upgrading`), and `scripts/changelog/fold.py` puts the fragments at the top of the matching sections under Unreleased, ordered by section and then file name, and removes them; run again with none left it changes nothing. `--check` validates the fragments (known section, not empty, no conflict marker) without writing, and the lint job runs it. Entries already in `CHANGELOG.md` stay where they are. Tooling and process only; no run changes.
