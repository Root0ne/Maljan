### Fixed

- **The report's body prints every table cell whole (T-399).** A model-written cell (§5.6 commands, §5.7 channels, §8 procedures, configuration values), a persistence target or payload, a command line, a URL or user agent, a registry key or value name, a string of note, a directed-text phrase, a signature description and the rows of a body evidence section were cut at 240 (or 160, or 80) characters and ended in `…`, with the whole text only in the JSON report; the HTML report, drawn from the markdown, lost the same text. Each is now printed whole in its row: the page wraps it, and the HTML stylesheet already breaks a cell wherever it must. The PDF prints tables with a fixed layout, so a kilobyte-long command line from the sample no longer makes the layout measure every word (a 10.5 KB cell took 136 s, now under a second), and every word is kept. Appendix A still cuts a long one-line value and says under it where the value is whole.
- **Every STIX indicator indicates the sample (T-402).** Only the sample's hash indicator and the indicators the judge related had an `indicates` edge; a mutex, a domain and every other row the export minted were published related to nothing. Once the integrity pass has folded duplicates, each indicator the bundle relates to no malware object gets an `indicates` edge to the object that stands for the sample, described as the platform's own so a consumer tells it from the judge's, and named by the report object. The judge's edges are kept as written, and an indicator the judge related by any other type (`related-to`) is not upgraded; an indicator typed `benign`, the similarity digests (imphash, ssdeep, TLSH match files that are not the sample) and a Benign export (no malware object) get none; the judge's own bundle is not edited.
- **A claim mapped to several techniques is one claim (T-406).** The reader keeps one claim per technique id a TECHNIQUE line lists, and the coverage check numbered and listed each copy: §13.1 repeated one claim once per technique, the run summary's per-analyst claim count counted every copy, and the report models' list of claims in force showed each copy under its own label. Each is now read by its block: numbered once, listed once in §13.1 with its techniques together in the row (`ClaimNotDiscussed.technique_ids`), each with the note the ATT&CK table prints for an id the catalogue lacks or an absence claim kept when asked, and counted once. The ATT&CK table, the matrix and `ttp_mappings` keep one row per technique.
