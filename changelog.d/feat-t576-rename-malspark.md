### Changed

- **The product is Malspark everywhere (T-576).** The Python package and distribution are `malspark` (`import malspark`, the `malspark` command), environment variables start with `MALSPARK_`, the containers, images, networks and the compose project (`name: malspark`, so volumes are `malspark_<volume>`) use the new name, and so do the Postgres database and user defaults, the Qdrant collection defaults, the MinIO bucket default, the entry-point groups plugins register under, logger names, the WebSocket subprotocol, the refresh cookie, the token issuer and audience, the console's browser storage keys and page titles, generated rule names, download file names, STIX custom properties (`x_malspark_*`), the settings export format (`malspark-settings/3`) and the job package format (`malspark-job-package/2`). The repository is https://github.com/Root0ne/Malspark and its GitHub Pages path is `/Malspark`. What stays as it was: an export or a job package written before still imports and verifies, a STIX bundle stored before is served under the new property names, and the hash-chain domain tags and key labels the evidence ledger, the audit chain and package signatures were written under are unchanged, so every stored chain, seal and signature still verifies (`malspark.core.previous_name`).

### Upgrading

- **Carry a deployment across before starting the renamed stack (T-576).** Stop the old stack without removing its volumes and run `scripts/upgrade/rename-volumes-and-env.sh`: it prints the plan, and with `--apply` copies the old volumes into the new names and renames every key in `docker/.env` that has the old prefix to `MALSPARK_`, printing key names only. It also prints how to rename the Postgres database and role or keep them, how to point memory at the existing Qdrant collections, and how to copy the stored samples into the new bucket. Signed-in sessions end once. `docs/upgrade-from-previous-name.md` walks through every step.
