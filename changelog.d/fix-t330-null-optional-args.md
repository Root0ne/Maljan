### Fixed

- **A tool call that gives `null` for an optional argument its server does not allow `null` for runs, as if the argument had been left out (T-330).** A model that filled every optional argument of a call wrote `null` for the ones it had nothing to say about, and a server whose schema types that argument without `null` refused the whole call: in the Claude Haiku 5.5 run of 2026-10-24, twelve Ghidra calls (`decompile_function` with `"program": null, "timeout": null`; `list_exports`, `list_imports` and `get_xrefs_to` with `"limit": null, "offset": null`) were lost to "Input should be a valid integer". At the tool boundary of every tool server, MCP and Ghidra's REST API alike, such a `null` is now dropped before the arguments are validated, so the field takes its declared default and the call is sent, recorded and compared for a repeat exactly as one that left the field out (`agents.null_arguments`). What decides it is the server's declared schema, never the tool: a field that admits `null` (its type includes `"null"`, it says `"nullable": true`, an `anyOf`/`oneOf` branch admits it, or nothing in its schema that is read rules `null` out; `allOf` and a `$ref` standing for the field's type are not read and keep the `null`) keeps an explicit `null`; a required field given `null` is refused with the same error as before; nested objects follow the same rule where the schema describes them, also behind a local `$ref` into `$defs`, each definition compiled once. The ledger entry names each field dropped (`args_nulls_dropped`) and each top-level `null` the schema admits but an MCP server is not sent (`args_nulls_withheld`: never sent, and recorded as its default, as a call that left it out is), each by its path segments; the call's `tool_call_started` event names both (`nulls_dropped`, `nulls_withheld`). Both fields are stored on the evidence row (two nullable JSON columns, migration `20261030000000`, sealed by the ledger chain only when set, so every stored digest stays what it was), served by `GET /jobs/{id}/evidence` and said as a sentence on the evidence panel's row; a row written before them reads as empty. Only the boundary can write these notes: an argument a model names like them is kept and recorded as an argument. The schema the model is offered is unchanged, a call with no such `null` is sent and recorded byte-identically, and stored runs carry neither field and read as before.
