### Added

- **Rule and document servers: YARA-X, oletools and webcrack, one container each, with their own pack steps (X24, X25, X27).** Three more built-in server blocks ship switched off, over the shared `services/cli-sidecar` plumbing as the identification servers are: `yarax` (YARA-X 1.21.0's `yr`: `yarax_scan`, the operator's own YARA rule files matched against any file, one row per matching rule with its metadata, tags and every matching string's offset), `oletools` (oletools 0.60.2: `ole_vba`, olevba's VBA source and keyword analysis with Excel 4 macro sheets and VBA stomping; `ole_macro_risk`, MacroRaptor's auto-run, write and execute flags; `ole_indicators`, oleid's indicators; `rtf_objects`, rtfobj's embedded objects with a digest of each payload; `office_dde`, msodde's DDE links) and `webcrack` (webcrack 2.16.0 on Node.js 22: `js_deobfuscate`, a JavaScript file or each script block of an HTA or WSF unminified, unpacked and cleared of self-defending and debugger traps), each with a `capabilities` tool. None runs what it reads: no macro runs, olevba's XLM emulator is neither installed nor allowed, an encrypted document is decrypted in memory with Office's default passwords and nothing is written to disk, and webcrack is handed no sandbox (its sandbox module is removed from the image), so an obfuscator's string-decoder calls stay as written and the declaration says so. Each report runs as a program of its own (`ole_report.py`, `deobfuscate.mjs`), in a process group of its own under `TOOL_TIMEOUT_SECONDS`. Each image pins its program by version and checksum (YARA-X's archive and binary; Node.js by its published sha256), its Python packages by hash (oletools and what it needs, wheels only, at the MCP SDK versions every sidecar pins) and webcrack's packages by integrity hash (`npm ci --ignore-scripts`). YARA-X is a server beside the shipped YARA scan, never the engine behind it: `yara_scan` and its pack step keep the platform's corpus as they were, and YARA-X reads only the operator's `*.yar` and `*.yara` files under `data/yara-x-rules` (or `YARA_X_RULES_DIR`), mounted read-only at `/data/rules` and compiled on each call; with none there every call is `missing_dependency` saying where the rules go. `yarax_scan` is declared as `yara_scan` is (kind `signature_rules`, rows `/matches/*`, the `rule` value, each string's `offset`, techniques from a rule's metadata), so its matches count as signature rule hits and corroborate as the one YARA layer (`source` `yara`), never as a second independent one. The compose file adds each under its own profile (`yarax`, `oletools`, `webcrack`), held as the identification sidecars are under the anchor they now share (`x-cli-sidecar`, renamed from `x-identification-sidecar`), with a 2g memory-and-swap ceiling each (`YARAX_MEM_LIMIT`, `OLETOOLS_MEM_LIMIT`, `WEBCRACK_MEM_LIMIT`), an internal network of its own and a bare relay (`yarax-port`, `oletools-port`, `webcrack-port`). Every tool is declared with its kind (`signature_rules`, `vba_macros`, `macro_risk`, `document_indicators`, `embedded_objects`, `dde_links`, `deobfuscated_script`), rows and values, routed formats, what it shows and does not show, read-only and running nothing. Five shipped pack steps, each off (no call, no entry) while its server is not switched on, run on the routed format alone: `ole_vba` on `ole2` and `ooxml`, `office_dde` on `ole2`, `ooxml` and `rtf`, `rtf_objects` on `rtf` and `js_deobfuscate` on `js`, `hta` and `wsf`, after the identification steps; `yarax_scan` on every sample, right after `yara_scan`. A deployment without the servers runs the pack as before, and stored runs replay identically.
