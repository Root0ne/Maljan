### Changed

- **A reputation service is read from what it lists and answers; the platform ships no table of VirusTotal's tools (T-418).** The built-in VirusTotal server's per-tool declarations (the answer paths, rank, display name, `discloses_sample` and the effects of each tool) are gone. For any server whose block's `roles` hold `reputation`, each tool its server does not declare is read from its MCP definition when it is listed (`core.derived_declarations`): a tool that sends the file, or a write tool (not marked read-only, or marked destructive), is a submission, so the triage pack never calls one; only a tool marked read-only and not destructive is read as asking: a submission's status when it takes a submission's id (`third_party: hash`), a reputation lookup when it requires the sample's hash (`third_party: hash`), a report on an indicator when it requires a domain, address or URL (`third_party: no`); `network: true` unless `openWorldHint` is `false`. A new server-level declaration field, `reputation_service` (`name`, `rank`), is laid under each lookup read so; VirusTotal's catalog entry gives `{name: VirusTotal, rank: 10}`, so its lookup keeps its name and is asked before the threat-intel sidecar (rank 20) as before. Such a lookup names the new `reputation_shape` reader and, while no declaration in force sets a `reputation` block or a reader of its own, its answer is read by its shape (`core.reputation.read_shape`): the engine tally (at least three whole numbers, never a vote, the object counting the most verdicts), the labels (label or family, then threat names, then threat categories), the detections, the earliest first-seen and latest last-seen date, the report link and the service the counts are attributed to, within eight levels and 20,000 members; a stored entry whose facts name no reader reads as it always did. Whether a tool sends the sample is read for every server and every tool: a tool that takes the file's content as bytes is `discloses_sample`, unless a server its block trusts marks it both read-only and closed, and a tool that takes a path or a file is unless it is marked closed; a tool that says it submits or uploads and takes either always is, and one that says so and is not marked read-only is whatever it takes. Every schema form of an argument is read (local `$ref`, `anyOf`/`oneOf`/`allOf`, array items, nested objects one level down). Read-only never excuses sending; an undeclared local tool that takes a path is shown as an upload until it is marked `openWorldHint: false` or declared. The reading is dropped only where the block itself says what the tool sends, or where a server the block trusts declares the tool. A definition that cannot be read is read as sending the sample, and a listing that cannot be read keeps the reading made before. The triage pack asks only a lookup its server's `tools` list ticks, where the block names one. The zero-cost rehearsal's gate disables a server whose block's `roles` hold `reputation` as one that reaches a third party, whatever its tools are read as, so VirusTotal is still switched off as reaching one where its listing is not yet read. What is read is kept with the server's declaration past the process, and a job lists an enabled reputation server of which nothing is kept before its run. VirusTotal's role, service, report URL and credential step now sit in its catalog entry (`core.virustotal`). A stored change of a tool whose kind comes from that reading and that names no kind of its own (a rank-only change of VirusTotal's lookup) keeps its fields: they are laid over the reading once it is listed, so the lookup is asked at the stored rank as before. Every stored VirusTotal file report reads the same record as before (62 answers, 0 differences in any field), every other VirusTotal tool reads the same kind and effects, and every stored run replays as before. When a report gives several, first seen is now the earliest date and last seen the latest, and a lookup's `shows` line names "the service" where it named VirusTotal.
