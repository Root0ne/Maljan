### Fixed

- **A tool whose rules are missing is named before the job, not only in its degraded block (T-492).** A run was accepted with nothing named unavailable and then lost capa: its library was installed, but its rules directory, which is fetched rather than tracked, had never been fetched into the run's worktree, and the check before a job looked only at libraries and executables. A tool's declared needs may now include a data path (`capabilities.data`: its default path, the setting that hands it another, the server variable that overrides it), and `POST /jobs` and the system status name a tool whose declared path is missing or a directory holding no file, with the path, what named it and how to put it there. The built-in sidecars declare capa's rules (`static.capa.rules_dir`) and the Sigma corpus (`MALJAN_SIGMA_RULES_DIR`, else `data/sigma_rules`), the two corpora a fresh clone or worktree lacks until `make external` has run. It is a warning, as for a missing library; a server's own manifest does not probe the path, and a tool that declares no data is checked as before, so no run changes.
