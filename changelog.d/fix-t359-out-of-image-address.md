### Fixed

- **A failed static call given an address outside the loaded image is told the image's range (T-359).** A model that dropped a hex digit asked a static server for bytes below the image and was answered only that the bytes could not be read, so it could not correct itself. Now such a failure carries one more line, also added to the ledger entry's remediation after the server's own: `address 0x1360bcfa00 is outside the image 0x1360bc00000–0x1360bc131ff (did a digit drop? in-image addresses here have 11 hex digits); pass an address inside the image`. The range comes from facts the run already holds: the server's own program statement (image base to last address), else the pack's one image base and the image size or last section its answers state. A call is read by its tool's declared `address` argument and only where the tool declares that it does not run the sample's code, so it covers every declared static server (Ghidra, radare2 or an operator's) and never picks a tool by name. The server's own answer and remediation stay as they were. A call that answered, an address inside the image, an address given as a name (letters alone, with no `0x` and no digit), digits alone that, read as decimal, fall inside the image, a call naming another program, a call naming none after the agent named a program other than the range's (any program, for the pack's range), and a run that holds no range are unchanged; the call is still sent, so a server that maps more than the image answers such an address as before.
