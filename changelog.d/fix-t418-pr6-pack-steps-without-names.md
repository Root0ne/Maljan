### Changed

- **The triage pack takes a server's tool as a step by what its declaration says, never by a server's or a tool's name (T-418).** The shipped list of pack steps now holds only the platform's own steps; the ten shipped steps that named a server and its tool (Detect It Easy, ILSpy, GoReSym, oletools, webcrack, unblob, JADX, YARA-X) are gone. In their place every configured server gives a step for each tool whose declaration in force answers one of the pack's server-step kinds about the whole file (`identification`, `type_list`, `function_list`, `signature_rules`, `vba_macros`, `dde_links`, `embedded_objects`, `deobfuscated_script`, `extracted_files`), is read-only, takes the file by its `path` argument, and declares that it runs none of the sample, reaches no network and sends nothing to a third party. A tool that would disclose the sample, or does not say, is never a step the pack takes on its own, nor is any tool of a server on another host that mounts none of the samples (the sample would be sent to it); an operator's step may still name either. Each step runs on the routed formats its tool declares, writes the files its tool declares in the new `outputs` field, and, for a tool that declares the one code runtime it reads in the new `runtimes` field, runs only where an identification answer's `runtime` value names it: Detect It Easy's server now gives each detection the runtime its name is (`dotnet`, `go`), and ILSpy's and GoReSym's servers declare theirs, so the conditions read a generic value instead of Detect It Easy's own names. Steps are placed after the platform's own step of the same kind (YARA-X after `yara_scan`), else after the format readers, identification first, then by server and tool, and each line names its tool and what it answers ("GoReSym · functions"); a server under any name whose tools say the same gets the same steps. An operator's step of the same tool on the same server is that tool's step, keeping its id and fields; a declaration in `triage.steps` with no server and no tool under an id no shipped step has is laid over the server's step of that id. A save knows the configured servers' steps and refuses a name none of them nor the list gives; a stored list keeps such names for the run to resolve, which says when a named step is no step of the run. A server trusted to declare its tools that has not been listed yet is off, saying its tools are not known, and what such a server declared is kept for one release, so a new release lists it again. With the shipped servers on, the pack runs the same steps on the same samples, with these differences: GoReSym's `go_types` is now a step beside `go_symbols`, oletools' steps run in tool-name order (`office_dde`, `ole_vba`, `rtf_objects`), the not-run sentence of a runtime step names the `runtime` value, the entries of these steps carry their step (`pack_step`) and its label, and a run that calls no tool server no longer lists the server steps as off. The platform's own step that starts beside the pack is found by its implementation, not its id. Every stored run replays as before.
