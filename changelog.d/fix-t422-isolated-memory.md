### Added

- **A job can have long-term memory of its own (T-422).** The job option `isolated_memory` (`POST /api/v1/jobs` config) files the job's long-term memory under the job alone (its owner's key with `/job/` and the job's id after it, `long_term_memory.memory_owner_for`), in the analysis worker and in the enrichment of its report alike. The judge's similar cases, the attribution's similar samples, the function-hash families and the earlier run then read nothing another job stored, for any sample, and the job's own case never replaces the case its owner held for the sample. Without the option the owner is the job's creator, byte for byte as before. The option is strict (only `true` or `false`), named in the job's audit row, and never reaches the job's settings. The stored run summary and the report's say `isolated_memory: true` for such a job and are unchanged for every other. A case corpus mined from the memory (`scripts/knowledge/build_attck_case_kb.py`) is not owner-scoped: every job reads it, an isolated one included; it holds unscoped cases alone. The command line has no such option: its runs use the unscoped memory.

### Fixed

- **A benchmark series no longer reads what its earlier runs stored for other samples (T-422).** `ignore_earlier_runs` kept a run from its own sample's earlier case only; run k of a series under one account still read, through the similar cases, the similar samples and the function-hash families, the cases runs 1..k-1 stored for the other samples. Every benchmark run is now also submitted with `isolated_memory` (`scripts/benchmark/jobs.py`; `python scripts/benchmark/run.py job-config` prints both switches, and the intel-off arm's job config carries them). `--with-earlier-runs` leaves out both. `score` and `gate` now count a run as independent only when its run summary says both `earlier_runs_ignored: true` and `isolated_memory: true`, or its score states `**Memory:** fresh account` on a line of its own; any other run is named under `EARLIER RUNS NOT RULED OUT` with the switch its summary does not say. Every isolated job adds one case and its function hashes under a key nothing reads; no purge by owner exists yet.
