### Fixed

- **A capability reference resolves, and settings save, before any tool server was listed (T-483).** On a settings database that keeps no declaration its servers served (a fresh or cloned one), every save was refused with "references capability 'reputation', which no tool server declares a tool of", and the built-in agents' reputation reference resolved to no server at run time. A capability now stands for every built-in server whose block's roles name it or whose declared tools are of its kind, whether or not its own `agents` list binds it to an agent, so the threat-intel sidecar is reached by every agent that references reputation, before and after its tools are listed. A save is not refused for a capability reference while an enabled built-in server has not been listed yet, since it may serve it once listed; such a save is answered with a warning naming each capability that resolves to no server yet and the servers still unlisted, and a run records "capability '…' resolves to no server" among the agent's degradation reasons. The static, network, triage, Android static and reverser analysts now hold the threat-intel sidecar's lookups beside VirusTotal's: each prompt carries those tools' schemas too, and their lookups share the reputation keys' rate limit with the judge's.
