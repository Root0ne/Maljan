### Fixed

- **A stage's key is shown in clear again, and with it every server, agent and prompt that says the same word (T-506).** The store holds a team as a plain map, and each stage's name sits under `key`, a word the credential rule reads as a credential in a tool server's `env` or a query. Read by its name, every stored stage key (`analysis`, `reversing`, `android_static`) was registered as a secret value, so the console masked it wherever it stood: the stage, the server and the agent of the same name, a stage's `depends_on`, and the word inside every prompt. Saving an edited team after that read was refused, because the masks had nothing stored behind them. A stored map is now read as the settings model declares it (`settings_catalog.configured_secret_values`): a declared field is a credential where the model types it as one (a `SecretStr`, an `api_key` or `auth_token`) or where its name names one, unless the model holds its value to a name pattern, as it does a stage's `key`; a test refuses a credential field given such a pattern. Every other value read as a credential before is read as one still, whatever word it is: an entry no model declares (a plugin's block, an `env` or `headers` entry) is read by its name, and a URL password, an encrypted row and a typed credential are held as before, even where they equal a server's, an agent's or a setting's name.
