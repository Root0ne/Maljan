### Fixed

- **A stage's key, and every name the settings give a server, an agent or a profile, is shown in clear again (T-506).** The store holds a team as a plain map, and each stage's name sits under `key`, a word the credential rule reads as a credential in a tool server's `env` or a query. Read by its name, every stored stage key (`analysis`, `reversing`, `android_static`) was registered as a secret value, so the console masked it wherever it stood: the stage, the server and the agent of the same name, a stage's `depends_on`, and the word inside every prompt. Saving an edited team after that read was refused, because the masks had nothing stored behind them. A stored map is now read as the settings model declares it (`settings_catalog.configured_secret_values`): a declared field is a credential where the model types it as one or where its name names one, unless the model holds its value to a name pattern, as it does a stage's `key`. A name the settings give something (any mapping key, a stage's key, a setting's own name) is never held, wherever a key misreads it, so a plugin block's credential-named entry that holds a server's name keeps the name shown, while one that holds anything else is held as before. What the catalogue types a secret (a `SecretStr`, an `api_key` or `auth_token`) is held whatever it reads as, so an API key written as a provider's name (`ollama`) is still masked; every value an `env` or `headers` entry, a URL password or an encrypted row holds is held as before.
