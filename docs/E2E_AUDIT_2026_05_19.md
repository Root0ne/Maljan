# Maljan — End-to-End Audit (2026-05-19)

> Successor to `docs/E2E_AUDIT_2026_05_17.md`. The prior audit (15 defects)
> is fully fixed, validated, and live-verified. This audit catalogues
> defects + improvement areas surfaced by the **second live run** on
> `zararli.apk` (job `76711f98-508f-43a6-853c-6c37442d93a4`, duration 969.9 s,
> Verdict=Malware confidence 0.986) plus three parallel codebase explorations.

## Executive summary

The 2026-05-19 zararli.apk run **completed cleanly per the previous audit
gates** (Pipeline mode REAL, 2946 Sigma rules loaded, 12/165 Ghidra tools,
all STIX UUIDs valid, all attack-patterns carry MITRE external_references,
no hallucinated indicators). However it also exposed a **new class of
silent-degradation defects** that the 2026-05-17 audit could not have
caught with a single ELF sample:

- All three LLM analysts produced **zero useful claims** because the
  Triage normalization layer leaked a Triage task-id into the sample
  filename, breaking Ghidra `load_program`.
- The final verdict still reads **Malware 0.986** — drawn entirely from
  YARA+Sigma deterministic layers. Nothing in the system signals
  "degraded run".
- Sigma rules without MITRE tags emit a hardcoded `T0000` placeholder
  technique that propagates into the STIX bundle as
  `attack-pattern--<uuid>(name=T0000, external_id=T0000)` — invalid per
  MITRE schema.
- The judge's `malware_category` ("rat") never lands in the report DB row.

Three additional audit dimensions also surfaced — security, observability,
performance — none of which were in scope for the previous audit.

**21 defects** documented across six categories. The first eight (Pipeline
Integrity) directly affect verdict correctness; everything else is
hardening.

## A. Pipeline Integrity (8 findings)

These directly degrade verdict correctness. **Sprint 1 priority.**

### APK-SAND-01 — Triage `sample.name` empty → task-id leaks into binary filename
- **Severity:** CRITICAL · **Effort:** Small
- **Symptom (live run):** Static analyst told to `load_program(file="260519-vny6sahx9s")` (a Triage task-id, not a filename) → `File not found` → "No static data available." Dynamic + Network analysts cascade-fail for the same root cause.
- **Root cause:** [src/maljan/loaders/triage_client.py:494](src/maljan/loaders/triage_client.py#L494) — `sample_name = raw_sample.get("name", task_id) if isinstance(raw_sample, dict) else task_id`. When Triage returns `"sample": {}` (empty), the fallback silently substitutes the task-id and propagates it into the normalized target's `file.name`. No warning is logged.
- **Cascade:** [src/maljan/core/container.py:289-291](src/maljan/core/container.py#L289) JSON-dumps target into the static analyst prompt; the LLM then asks Ghidra to open a file with that name.
- **Fix sketch:**
  1. Log a WARNING when the fallback fires: `"Triage returned no sample name; using task_id placeholder. Static analyst load_program will fail."`
  2. Substitute a sentinel like `_triage_no_name_<task_id>` instead of the raw task_id, so downstream errors are unambiguous.
  3. (Better) Back-fill `sample.name` from `overview.sample.target.name` if the summary's `sample` block is empty.
- **Test gap:** No fixture covers a Triage response with `"sample": {}` or `"sample": null`.

### CONF-INFL-01 — Final confidence not capped when LLM analysts produce nothing
- **Severity:** CRITICAL · **Effort:** Medium
- **Symptom:** zararli.apk run yields `corroborated_count=0, technique_count=11 (all single-layer YARA/Sigma)`, yet `overall_confidence=0.986`. A user reading the verdict has no way to know the LLM analysts contributed zero signal.
- **Root cause:** [src/maljan/pipeline/nodes.py:487-496](src/maljan/pipeline/nodes.py#L487) computes `final_decision` and `overall_confidence` purely from the judge LLM's bundle, which weights cascade techniques heavily (YARA=0.90, Sigma=0.55, with cross-layer multiplier 1.25). The LTM-01 quality gate (lines 541-566) recognises this is a degraded run for memory-storage purposes but does **not** mark the verdict itself.
- **Fix sketch:** After the judge node, apply a confidence floor:
  ```python
  if cascade_summary and cascade_summary.corroborated_count == 0:
      overall_confidence = min(overall_confidence, 0.60)
      degraded_mode = True
  ```
  Surface `degraded_mode` in `RunSummary` and the report DTO so the UI/CLI can render a "Unconfirmed: analyst engines produced no claims" banner.
- **Test gap:** No regression test asserts that a zero-corroboration run produces confidence ≤ 0.6.

### DYN-SAND-01 — Empty sandbox processes silently downgrade to placeholder
- **Severity:** HIGH · **Effort:** Small
- **Symptom:** Dynamic + Network analysts emit `"No dynamic data available for sample <sha>"` rather than a structured "evasion suspected" claim when Triage produces zero behavior events.
- **Root cause:** [src/maljan/loaders/file_loader.py:106-107](src/maljan/loaders/file_loader.py#L106) returns the fallback string anytime the JSON section is missing or empty. The parser never distinguishes "sandbox failed to run" from "sandbox ran but observed nothing".
- **Fix sketch:** In `dynamic_parser` / `network_parser`, when `behavior.processes == []` but the upstream sandbox reports `status: reported`, emit a structured single-claim ISR: `claim="Sandbox completed with no observable execution events. Possible anti-sandbox evasion (T1497) or platform mismatch (APK in Linux VM, etc.)"`, confidence 0.3. That gives the judge real signal instead of an empty fallback.

### SIG-T0000-01 — Sigma rules without MITRE tags emit `T0000` placeholder
- **Severity:** HIGH · **Effort:** Small
- **Symptom:** zararli.apk STIX bundle contains an `attack-pattern--<uuid>` with `name="T0000"` and `external_references=[{source_name: mitre-attack, external_id: "T0000"}]`. Two Sigma rules ("Sysmon Configuration Change", "Cleartext Protocol Usage") triggered this.
- **Root cause:** [src/maljan/analysis/sigma_layer.py:299](src/maljan/analysis/sigma_layer.py#L299) — `return "T0000"` when no `attack.t####` tag is found. The [ttp_cascade.py:259-267](src/maljan/analysis/ttp_cascade.py#L259) regex filter drops T0000 from the cascade, but the original Sigma `to_isr()` claims still feed into the judge prompt as text, so the LLM regurgitates them into the bundle.
- **Fix sketch:**
  1. Sigma adapter: return `None` instead of `"T0000"` when no attack tag exists; downstream callers already handle None.
  2. Judge post-processor: extend [judge_postprocess.py:143-158](src/maljan/agents/judge_postprocess.py#L143) (the REP-01 backfill) to validate `external_id` against `^T\d{4}(\.\d{3})?$` AND check against `_INVALID_TIDS` (already exists in `base_agent.py:38`).
- **Test gap:** No test covers a Sigma rule without attack tags; the hardcoded default is regression-prone.

### FILT-COVERAGE-01 — Judge invalid-technique filter only checks custom field
- **Severity:** HIGH · **Effort:** Small
- **Symptom:** `_filter_invalid_technique_ids` ([judge_agent.py:581-608](src/maljan/agents/judge_agent.py#L581)) only inspects `x_maljan_technique_id` (a Maljan-custom STIX extension). Standard STIX fields `external_references[*].external_id` and `name` are not validated. SIG-T0000-01 slips through specifically because of this.
- **Fix sketch:** Extend the filter to walk `external_references` and `name`, applying the same regex + `_INVALID_TIDS` set. Drop offending SDOs and `id_remap` references the same way J-01 handles UUID rewrites.

### PIPE-ANA-01 — Static analyst doesn't validate target path
- **Severity:** MEDIUM · **Effort:** Small
- **Symptom:** Static analyst calls `load_program(file="…")` with whatever string the prompt contains. If the path doesn't exist, the LLM gets a cryptic "File not found" tool error and hallucinates a fallback narrative.
- **Root cause:** [src/maljan/agents/static_analyst.py:327-329](src/maljan/agents/static_analyst.py#L327) — no path validation before invoking the ReAct loop.
- **Fix sketch:** Pre-check: if `target_info` references a path shorter than 512 chars AND `os.path.exists(path)` is False, short-circuit with an explicit AnalystError + an "input invalid" ISR. Saves a wasted LLM round and produces a clean error message in the report.

### CAT-PERSIST-01 — `malware_category` inferred but persisted as NULL
- **Severity:** MEDIUM · **Effort:** Small
- **Symptom:** Worker log: `Schema pruning: inferred category 'rat'.` (twice — once in judge, once in report node). DB row: `analysis_reports.malware_category = NULL`. Report DTO field is `None`.
- **Root cause candidates:** Most likely [src/maljan/pipeline/nodes.py:684-690](src/maljan/pipeline/nodes.py#L684) — the `infer_malware_category(...).value` call is wrapped in an `except Exception` with only a WARNING log; if the exception fires, `malware_category` stays None and nothing surfaces it. Alternatively the report-service mapper drops the field.
- **Fix sketch:**
  1. Make the `except` branch log at ERROR with the exception type+message.
  2. Add an integration test: end-to-end pipeline run on a sample known to map to a category → assert DB row's `malware_category` non-null.

### ANA-MARK-01 — Meta-claim detection missing
- **Severity:** MEDIUM · **Effort:** Small
- **Symptom:** When an analyst's only "claim" is a fallback string like "No static data available", the judge prompt sees it as a 1-claim, ~1.0-confidence report. Cascade and verdict downstream get polluted.
- **Fix sketch:** In `BaseAnalyst._text_to_isr()`, detect strings starting with `"No "` and containing `"data available"`. Flag the resulting ISR with a `_is_meta_claim` private attribute (or zero claims + a sentinel `dissent_items` entry). Judge & cascade skip meta-claim ISRs from mean_confidence and cascade contributions.

## B. Security & Auth (6 findings)

Not covered by the prior audit; surfaced via the new Explore pass.

### SEC-MINIO-BUCKET-ACL-01 — Sample bucket policy not set after create
- **Severity:** HIGH · **Effort:** Small
- **Where:** [apps/api/app/api/v1/samples.py:196-198](apps/api/app/api/v1/samples.py#L196)
- **Risk:** `client.make_bucket(name)` is called without immediately setting a private-only policy. If MinIO is misconfigured (or the bucket was created earlier with public read), uploaded malware samples are accessible unauthenticated at `http://localhost:9000/maljan-samples/<sha>`.
- **Fix sketch:** Immediately after `make_bucket`, call `set_bucket_policy(name, private_only_json)`. Add an integration test that issues an unauthenticated GET and asserts 403.

### SEC-WS-AUTH-CONTINUOUS-01 — JWT only validated at WS handshake
- **Severity:** MEDIUM · **Effort:** Medium
- **Where:** [apps/api/app/api/ws.py:167-176](apps/api/app/api/ws.py#L167)
- **Risk:** After connection, no token re-validation per message; a token that expires mid-stream stays valid until the connection closes. A revoked user keeps streaming events.
- **Fix sketch:** On each pubsub message, check the token's `exp` and a server-side revocation set; close the WS with policy code 1008 if invalid.

### SEC-TOCTOU-AUTHZ-01 — User row decode-then-fetch TOCTOU
- **Severity:** MEDIUM · **Effort:** Medium
- **Where:** [apps/api/app/deps.py:17-63](apps/api/app/deps.py#L17) + resource fetches in [samples.py:259-272](apps/api/app/api/v1/samples.py#L259)
- **Risk:** If the user is deactivated or deleted between `get_current_user` and the resource check (a few ms apart in DB terms), the request still completes.
- **Fix sketch:** Either (a) `SELECT FOR UPDATE` the user row when sensitive operations begin, or (b) re-check `user.is_active` immediately before the resource access using the same DB session.

### SEC-JWT-ROTATION-01 — JWT secret loaded once, never rotated
- **Severity:** MEDIUM · **Effort:** Large
- **Where:** [apps/api/app/auth/jwt.py](apps/api/app/auth/jwt.py)
- **Risk:** A leaked secret remains valid until every issued token expires.
- **Fix sketch:** Add a `kid` (key id) header; maintain a key-ring of N most-recent secrets; rotate the active key weekly via cron. Tokens signed under retired keys are honored for a configurable grace period (default 24 h).

### SEC-CORS-HEADERS-01 — No security headers middleware
- **Severity:** LOW · **Effort:** Small
- **Where:** [apps/api/app/main.py:129-137](apps/api/app/main.py#L129)
- **Fix sketch:** Add a tiny middleware that sets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security: max-age=31536000` (when TLS), and a minimal `Content-Security-Policy`. Helmet for Node has no direct Python equivalent, but `starlette` middleware is trivial here.

### SEC-MIME-DOUBLE-EXT-01 — `original_filename` not validated
- **Severity:** LOW · **Effort:** Small
- **Where:** [apps/api/app/api/v1/samples.py:79-90](apps/api/app/api/v1/samples.py#L79)
- **Risk:** Storage path uses sha256 (safe), but the API returns `original_filename` verbatim. Double-extension (`malware.exe.txt`) tricks careless downstream tooling.
- **Fix sketch:** Accept filenames matching `^[A-Za-z0-9._-]{1,255}$` and rejecting names with more than one `.` outside the final extension. Trim invalid filenames to a sha256-derived alias.

## C. Observability & Operations (5 findings)

### OPS-DEGRADED-VERDICT-01 — No `degraded: true` flag for partial-failure runs
- **Severity:** MEDIUM · **Effort:** Medium
- **Why this matters:** Operators reading the dashboard can't distinguish "the LLM analysts confidently agreed it's benign" from "two analysts crashed and we're guessing from YARA". Both render as identical Verdict+Confidence cards today.
- **Fix sketch:** Add `RunSummary.degraded_mode: bool` + `failed_analysts: list[str]` + `degradation_reasons: list[str]`. Render a yellow banner in the web UI and a `[DEGRADED]` prefix in CLI output. Tightly coupled to CONF-INFL-01 — pair them in the same sprint.

### OPS-ANALYST-ERROR-TRACKING-01 — No metric on analyst errors
- **Severity:** LOW · **Effort:** Small
- **Fix sketch:** Either emit `event_type=analyst_error` structured logs that Loki/Promtail can scrape, or add a Prometheus counter `maljan_analyst_errors_total{agent}`.

### OBS-TTP-ATTRIBUTION-01 — Per-layer TTP counts not in summary
- **Severity:** LOW · **Effort:** Medium
- **Fix sketch:** Extend `CascadeMetrics` with `techniques_by_layer: dict[str, int]` and render `1 yara · 9 sigma · 1 network · 0 static · 0 dynamic` in `RunSummary.to_markdown()` and the report DTO.

### OBS-ANALYST-ERRORS-METRIC-01 — `RunSummary.analyst_failures` missing
- **Severity:** LOW · **Effort:** Small
- **Fix sketch:** Add a field; populate from the same place that catches analyst exceptions in `pipeline/nodes.py:130-147`.

### OBS-STRUCTURED-LOGS-MISSING-FIELDS-01 — Analyst error logs lack key fields
- **Severity:** LOW · **Effort:** Small
- **Fix sketch:** Wrap analyst dispatch with `time.perf_counter()` and emit `logger.error("...", extra={"job_id": ..., "agent": ..., "duration_ms": ..., "tool_calls": ...})`.

## D. Performance & Cost (2 findings)

### PERF-STATIC-ANALYST-LATENCY-01 — Static analyst routinely 10+ minutes
- **Severity:** HIGH · **Effort:** Large
- **Symptom:** zararli.elf (prior run) static analyst: ~10 min. zararli.apk (this run): static failed immediately because of APK-SAND-01, so we don't have a fresh measurement.
- **Fix sketch:**
  1. Instrument the ReAct loop in [base_agent.py:90-231](src/maljan/agents/base_agent.py#L90) with per-step timing (LLM ms, tool ms, tokens out).
  2. Set a per-step Ghidra call budget (e.g. 15 calls max); abort with a partial ISR if exceeded.
  3. Cache `load_program` / `get_current_program_info` results across analysts for the same sha256.

### PERF-PARALLEL-ANALYSTS-01 — Concurrency unverified
- **Severity:** HIGH · **Effort:** Large
- **Fix sketch:** Add a unit test that asserts `analyst_started_at` timestamps for all three agents lie within a 5 s window. If they don't, switch the LangGraph wiring to explicit `asyncio.gather` over the analyst nodes.

## E. LLM Provider Portability (2 findings)

### PORTABLE-TIMEOUT-QUIRKS-01 — Per-provider timeout APIs aren't abstracted
- **Severity:** MEDIUM · **Effort:** Medium
- **Fix sketch:** Add `BaseLLMProvider.set_timeout(seconds)`; per-provider implementations route into the right place (`request_timeout` for OpenAI, `keep_alive` for Ollama, raw `httpx.Timeout` for the Anthropic provider).

### PORTABLE-RESPONSE-FORMAT-01 — `with_structured_output` silently fails on Ollama
- **Severity:** MEDIUM · **Effort:** Medium
- **Fix sketch:** Add `BaseLLMProvider.supports_structured_output: bool`. When False, skip `with_structured_output(...)` upfront and use a JSON-tag prompt + post-parse instead. Today the exception path falls back to regex extraction with no log, silently degrading the mediator's verdict structure.

## F. Frontend Resilience (2 findings)

### FE-WS-RECONNECT-TEST-01 — Exponential backoff has no e2e test
- **Severity:** LOW · **Effort:** Medium
- **Fix sketch:** Add `apps/web/e2e/ws_reconnect.spec.ts` that stubs the WS, kills it, asserts backoff delays grow (1 s → 2 s → 4 s …), and the UI shows "Reconnecting…".

### FE-TYPE-SAFETY-DRIFT-01 — No runtime validation of API responses
- **Severity:** LOW · **Effort:** Small
- **Fix sketch:** Introduce `zod` schemas alongside the existing TS interfaces; parse every fetch response through them. Emit a console error + Sentry breadcrumb when a schema doesn't match, so API/frontend drift is caught early.
