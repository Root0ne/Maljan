\section{Reproducibility}
\label{app:repro}

The harnesses, the derivation of every number in this paper, the per-sample records they read and
the scripts that build the figures and assemble this document are released with the paper under
\texttt{tests/evaluation/}, checkpointed and resumable, with the repository recording which harness
produced which result. Everything procedural therefore lives there, and this appendix carries only
what a reader needs in order to interpret the measurements rather than to re-run them.

\subsection{How the numbers get onto the page}\label{numeral-policy}

Every number this paper states about its own results is generated from the committed per-sample
records into a macro and referenced, never typed, and a key the document asks for that the
derivation cannot produce stops the build rather than leaving a hole in the page. The reason is
drift rather than tidiness. Over this project's history the same measurement was typed into five
places and went stale in all of them, and a figure caption disagreed with the paragraph beside it
for a month.

Three kinds of number are deliberately literal and marked as such at the point of use, so that a
reader can tell a deliberate exemption from an oversight. Settings, such as a port or a step budget,
which no analysis produces and which cannot go stale; the distinction is not visible in the digits,
since \setting{31}\,GiB of host memory is a setting and \fact{paged-out-working-set} paged out is a
measurement. Values quoted from cited work, registered with the citation each belongs to and
permitted only on a line carrying that citation, so a quoted figure cannot drift away from its
source. And observations from diagnostic sessions whose raw output was never in scope for the
retention rule, each registered with the dated record that carries it and presented as an
observation rather than as a measurement from the archive. A check enforces all three, and refuses a
declared setting whose value is one the analysis already derives, because that would be a way of
laundering a measurement into a constant.

Naming the imatrix dataset matters. Most papers reporting a quantisation level cannot say which
calibration produced it, and two IQ3 quants of the same model are not the same artefact.

The engine is \texttt{ik\_llama.cpp} at commit
\texttt{\seqsplit{eb570eb96689c235933b813693ca28ab9d3d26de}}, \emph{``MTP: Avoid per step SSM copy
(\#\fact{engine-commit-pr})''}. The binary could not identify itself, because
\texttt{llama-server\ -\/-version} prints \texttt{version:\ 0\ (unknown)} on a build tree that was
never a git checkout. The commit was recovered from a depth-\setting{1} clone vendored elsewhere in
the project and then \emph{proved} to describe the build, with identical \fact{engine-source-files}-file
source lists and, once line endings are normalised, exactly one file differing. We report the
reconstruction rather than presenting the identifier as though it had been recorded, because build
provenance must be captured at build time.

\begin{verbatim}
llama-server -m Qwen3.6-35B-A3B-IQ3_K_R4.gguf \
  -c 131072 -t 16 -fa on -ctk q8_0 -ctv q8_0 -ngl 999 \
  -ot "blk\.([1-3][0-9])\.ffn_(up|gate|down)_exps=CPU" \
  --context-shift on --jinja --host 0.0.0.0 --port 8080
\end{verbatim}

The context is served at \fact{context-served}, half the model's native \setting{262,144}, and the
launch command documented in the repository at one point specified \texttt{-\/-n-cpu-moe\ 36} while
the service ran \fact{cpu-offload-blocks} blocks on CPU. The command above is what ran.

The host is a single RTX \fact{host-gpu} with \setting{31} GiB of RAM and \setting{16} threads, and
four measured properties bound what can be reproduced on it. \texttt{llama-server} grows with
cumulative requests and does not plateau, from \fact{llama-rss-fresh-gb} GB fresh to
\fact{llama-rss-growth-gb} GB after a single full analyst pass and \fact{llama-rss-sustained-gb} GB
after \fact{llama-rss-sustained-minutes} minutes of multi-arm load. The growth is anonymous and
unreclaimable, so a long paired run must restart the server between arms, which changes no decoding
parameter and is therefore measurement-neutral. Serving at \setting{64}k instead of \setting{131}k
does not lower the peak, at \fact{llama-rss-64k-gb} against \fact{llama-rss-growth-gb} GB, because
the baseline is CPU-resident expert weights and the growth follows the context a pass actually
consumes. Generation varies from \fact{generation-rate-high} to \fact{generation-rate-low} tokens/s
across requests, because on this hybrid recurrent architecture llama.cpp writes and erases a
\fact{recurrent-checkpoint-mib} MiB recurrent-state checkpoint every few hundred tokens at
\textasciitilde39k tokens of context, so long-context calls are not slow in proportion; they fall
off a cliff. And the Ghidra container is capped at \fact{ghidra-mem-limit-gb} GB, its JVM
\texttt{-Xmx4g} bounding the heap only, with measured RSS reaching \fact{ghidra-rss-gb} GB against
that nominal \fact{ghidra-jvm-heap-gb} GB cap.

The working set does not fit alongside an interactive session, and that is a reproducibility fact
rather than an operational one. Model server \textasciitilde16 GB, analysis worker
\textasciitilde8 GB and disassembly container up to \fact{ghidra-mem-limit-gb} GB leave nothing on a
\setting{31} GiB host, and arms measured under memory pressure are not commensurable with arms that
were not. Long paired studies here are therefore run against an otherwise-idle host, and the
harnesses record \texttt{MemAvailable}, \texttt{SwapFree} and the model server's
resident-versus-swapped split at both ends of every arm. That screen can only be applied forward,
because for arms already collected without it the state is gone and the honest label is
\texttt{unattributable}, which is what Section~\ref{the-host-as-an-uncontrolled-variable} reports it
cost.

\subsection{Data and the sandbox}\label{data}

The dynamic cohort is n=\fact{cohort-n}, Windows PE only, stratified by year at seed
\fact{cohort-seed} with its digest recorded. The withdrawn drift study's manifest survives as
\fact{drift-n} dated samples over \fact{drift-cohorts} cohorts and \fact{drift-families} families,
metadata only and no binaries, so that cohort can be reconstructed even though its results cannot.
Per-sample outputs are stored for every study in this paper, a policy adopted after their absence
cost us a result. Ground truth resolves a MalwareBazaar family signature to an in-repo MITRE
\texttt{uses} fixture through an explicit alias map plus a CamelCase-split fallback, and it is
uncurated at technique level, which Threats to Validity treats as a construct-validity limit rather
than a footnote.

The sandbox is CAPE 2.5 at a private address, reachable only from one network. It has one analysis
machine and no Linux VM, so only Windows PE can be analysed dynamically whatever the code's stated
scope, and an ELF submitted there joins the \fact{cape-backlog} tasks that are never scheduled.
Reports are retained for days rather than indefinitely: sampled across the full task-id range,
\fact{cape-report-retention-sampled} of \fact{cape-report-retention-sampled} older tasks return
\texttt{"Reports\ directory\ does\ not\ exist"} while a report from four days earlier survived, so
the local archive of fetched reports is the only copy and submitting the same samples is not a
reproduction recipe on its own. The instance also rate-limits, and its throttle response is
byte-identical to its auth refusal, \texttt{\{"error":\ true,\ "message":\ ""\}} in both cases, so a
harness that reads that string as a capability verdict will mis-classify a throttle as a missing
permission, as we did briefly; re-calling a tool that worked minutes earlier tells them apart. A new
Windows submission is scheduled in \textasciitilde1 second and completes in \textasciitilde5.5
minutes, which makes an n=\fact{cohort-n} cohort roughly \fact{cohort-sandbox-hours} hours of sandbox
time.

\texttt{enable\_thinking} is honoured on DashScope and ignored on OpenRouter. Not rejected, but
accepted, recorded in the result file, and not acted on. The re-run requesting it returned a
\fact{arm-default-nothink-reasoning} reasoning share against \fact{arm-default-reasoning} without it,
while on DashScope the same request produces \fact{arm-qwen35ba3b-nothink-reasoning}. This is the
line in this appendix that matters most to anyone comparing arms, because the flag is worth
\fact{reasoning-flag-worth-low} to \fact{reasoning-flag-worth-high} F1 on the two models where it can
be set, and an arm can therefore be labelled matched while running the opposite configuration.
\texttt{eval\_parameter\_size\_series.py} selects arms on the measured reasoning share for exactly
this reason, and refuses to correlate when fewer than three configuration-matched arms span three
parameter counts, which on these endpoints is always.

The local server's output cap must be sent twice. \texttt{ChatOpenAI(max\_tokens=N)} reaches the wire
as \texttt{max\_completion\_tokens}, which \texttt{ik\_llama.cpp} does not read, so the cap must also
travel in \texttt{extra\_body} as \texttt{max\_tokens} and \texttt{n\_predict}. Measured on this
host, \fact{cap-requested} requested yields \fact{cap-ignored-tokens} generated with the renamed
field alone and \fact{cap-honoured-tokens} with both. That server also truncates silently, returning
\texttt{finish\_reason:\ "stop"} at the cap and never \texttt{"length"}, with no
\texttt{stopped\_limit} field, so telemetry that detects truncation by finish reason will report zero
however often the cap binds. Compare the generated-token count against the cap that was requested
instead.

The frontier arm ran on a free tier allowing \fact{openrouter-daily-limit} requests per day with a
\fact{openrouter-burst-limit}-per-minute cap that applies whether or not credit has been purchased.
The first attempt exhausted the daily quota mid-flight, \fact{quota-calls-landed} calls landing and
\fact{quota-calls-refused} returning HTTP 429, and the n=\fact{superseded-frontier-n} estimate it
produced was not merely imprecise but pointed the wrong way
(Section~\ref{frontier-does-not-separate}). The arm reported here is the completed
n=\fact{arm-default-n} run from a fresh quota. The quota governs what a cohort-scale frontier arm
costs in wall-clock rather than in dollars, since one call per sample over a \fact{baseline-n}-sample
cohort is two days at that rate and a full-pipeline arm, at roughly \fact{requests-per-analysis}
model requests per analysis, is not reachable on the free tier at all.

\subsection{Two checks worth running before the studies they check}\label{reproducing-each-result}

Two harnesses exist only because a result could not be believed.
\texttt{verify\_b3\_mechanism.py} recomputes each ablation arm's cascade set from its seeded fixture
and compares it against what the arm recorded; it is what established that a published finding of
ours had measured the reconciliation step rather than a model.
\texttt{probe\_outbound\_parameters.py} asks whether the server acts on each parameter we send it, by
behaviour rather than by reading a response field, because a server that ignores a parameter does not
report having done so. Separately, the judge-contribution study is run twice and the pair is kept,
once with the output cap not reaching the server and once with it binding, because the comparison
between the two is what isolates what the model's unparsable output contributes and neither run alone
shows it.

Figures are generated from the same retained records as the text, with intervals recomputed by the
seeded bootstrap rather than read out of a summary, so a figure and a sentence cannot drift apart
without the script failing to reproduce one of them. This caught a live error. An ROC computed by
naive descending sort returned AUC \fact{confidence-auc-naive-legacy} against the
\fact{confidence-auc} in our text, because \fact{confidence-modal-count} of \fact{confidence-n} claims
are tied at confidence \setting{1.0} and tie handling decides the entire estimate. The text was right
and the first draft of the figure was wrong, which is the ordinary direction for this check to fire
and the reason for wiring it this way.
